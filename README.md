# 守秘人笔记本 · Keeper's Local Notebook

> **导入模组 → 混合检索原文 → 分 7 阶段抽取 → 大部分实体化，全部可自由编辑 → 逐条跳回原文核对。**

一个把 COC 文字模组**实体化**的守秘人备本工作台：RAG 检索保证引文命中原文，分阶段 function calling 保证每一步都能人工介入，实体卡片与可编辑文档保证结论可改、可查、可复用。

## 30 秒了解

**这个工具是给谁用的？**

《克苏鲁的呼唤》（Call of Cthulhu，COC）是一款桌面角色扮演游戏，跑一次游戏需要一位主持人（**守秘人 / Keeper / KP**）提前读完几十页的**模组**（也就是剧本），记住人物、线索、分支和结局。

**痛点是什么？**

模组信息是「散落」的：同一个人物在不同章节出现、线索藏在正文中间、分支关系靠脑补。KP 备本时通常要自己写大量笔记，而且**笔记和原文脱节** —— 玩家问「这个 NPC 之前在哪见过」，你得翻回去找。

**这个工具做了什么？**

它不是「让 AI 读一遍给你总结」，而是走一条完整的**检索 → 实体化 → 可编辑**链路：

1. **混合检索（RAG）** —— 模组导入后会被切块，建立**关键词 + 向量**双索引。分析某个阶段时，按语义召回最相关的原文片段送进模型，而不是把整本模组硬塞进去。这既省 token，也保证引文能命中原文。
2. **实体化** —— 模型把召回内容抽成 **7 类结构化实体**：故事背景、时间地点、人物、怪物 / Boss、人物弧光、线索、幕结构。每类都是**独立的数据对象**，不是一段 Markdown 文本。
3. **全部可自定义编辑** —— 每张实体卡的所有字段都能改：人物属性、别名合并、关系标签、线索指向、幕的分支与关键事件、KP 笔记……AI 产出只是**起点**，最终以你的修订为准。
4. **可追溯** —— 每条结论都标注「原文事实 / AI 推断 / 原作矛盾」，并附**页码与原文引用**，点击即可跳回 PDF 那一页核对。

## 核心能力

### 1. 混合检索 + 实体化（RAG）

- 模组导入后切块，建立**关键词 + 向量**双索引（`lib/retrieval.ts`、`lib/embedding.ts`）
- 每个分析阶段按语义召回最相关片段，而不是把整本模组硬塞给模型
- 召回结果被抽成**结构化实体**（人物、怪物 / Boss、地点、线索、幕、人物关系）与**可编辑文字**（故事背景、人物弧光、时间线概要），不是一段不可拆的 Markdown
- 引用经 `lib/quote-check.ts` 校验，保证引文确实命中原文

### 2. 七阶段分阶段 function calling

不是一次性丢给模型，而是**七个阶段独立调用**，每阶段可单独失败、单独重跑：

| # | 阶段 | 产出实体 |
| --- | --- | --- |
| 1 | 故事背景 | 核心冲突、起因、历史、开局状态、各势力计划、可能结局 |
| 2 | 时间与地点 | 时间线概要、地点档案（含方位提示） |
| 3 | 人物 | 人物卡，含 CoC 7 版属性、技能与攻击 |
| 4 | 怪物 / Boss | 非人怪物、神话生物、野兽、无名敌人模板 |
| 5 | 人物弧光 | 经历、动机变化、与主线的关系；人物间语义关系 |
| 6 | 线索 | 来源、获得方式、错过条件、指向目标、卡关风险与补救 |
| 7 | 幕结构 | 幕划分、分支、关键事件（含 Boss 数据与 SAN 损失）、幕内行动 |

交互式确认基于 **tool calling** 实现（`ask_user` / `complete`），支持**暂停 → 人工裁决 → 后台继续 → 再次确认**，确认过程不阻塞分析。

### 3. 所有内容都可自由编辑（核心设计）

AI 产出只是**起点**。**无论是结构化实体还是文字内容，每一处都能改：**

**结构化实体卡**（字段级编辑）：

| 实体 | 可编辑内容 |
| --- | --- |
| 人物卡 | 属性、技能、攻击、别名合并、公开/真实身份、动机秘密、扮演提示 |
| 怪物卡 | 能力、弱点、战术、奖励、KP 专属信息、CoC 属性 |
| 地点 | 描述、方位提示 |
| 线索 | 来源、获得条件、错过条件、指向目标、卡关风险、补救方案 |
| 幕结构 | 标题、地点、涉及人物/怪物/线索、分支条件与后续幕、关键事件 |
| 人物关系 | 关系标签、方向、依据与剧情意义 |

**文字内容**（段落级编辑）：

- 故事背景（核心冲突、起因、历史、开局状态、各势力计划、结局）
- 人物弧光（经历、动机变化、与主线的关系）
- 时间线概要
- 任意章节的 KP 笔记与 Markdown 说明
- 文档原文可直接可视化编辑

所有修改随项目持久化，重跑分析时**以你的修订为准**（KP 裁决会作为上下文传给后续阶段）。

### 4. 每条结论都可追溯到原文

模型输出的每一项都带三个字段：

- `provenance`：`source`（原文明确）/ `inference`（AI 推断）/ `conflict`（原作自相矛盾）
- `sources[]`：PDF 实际页码、印刷页码、所属章节、原文引用片段
- `confidence`：0–1 置信度

**AI 不允许把猜测伪装成原文事实**，找不到依据时必须标为推断。

### 5. 书页翻页阅读与图片提取

- **书页翻页**：turn.js 驱动的翻页阅读器，支持单/双页切换、固定逻辑页等比缩放、目录跳转与页码定位
- **图片提取**：从 PDF / DOCX 提取内嵌图片，按页码与章节归档，可拖拽组成调查员图片资料包
- **双向跳转**：分析结论 ↔ PDF 原文对照

### 6. 幕树与人物关系图

- **幕树**：自动布局的分支时间线，节点**可拖动**并保存位置，支持「恢复默认布局」
- **人物关系图**：只保留有语义依据的关系，不靠「同框出现」凑数
- 两者都基于 `@xyflow/react`，分支切换时位置分别持久化

### 7. 导入真实模组，而不是纯文本

- 支持 **PDF**（依赖文字层）、**DOCX**、**Markdown**
- PDF **优先读取内置书签**，没有书签时回退到正文标题识别
- 自动**识别并排除目录页条目**，避免章节被重复提取
- **双栏排版自动分栏**，不会把左右栏拼成一行
- 章节范围可人工增删改，支持修正印刷页码

### 8. 数据留在你自己的浏览器

- 项目、导入的原文件、检索索引、向量空间**全部存在浏览器 IndexedDB**
- 服务端**只做一件事**：转发模型请求（无状态、不落库）
- 执行分析时，只有**你勾选章节**的文字会发送给你自己配置的模型服务商

### 6. 不锁定模型服务商

支持 **OpenAI 兼容 / Anthropic / Gemini / Ollama** 四种协议。切换协议时不会覆盖你手填的服务地址；若检测到「模型名与接口地址明显不匹配」会给出提示。

## 快速开始

需要 **Node.js 22.13+**。

```powershell
npm install
npm run dev
```

浏览器打开 `http://localhost:3000`。

首次使用需要在「设置」里填写模型服务信息：

| 字段 | 示例 |
| --- | --- |
| 接口协议 | OpenAI 兼容 |
| Base URL | `https://api.deepseek.com/v1` |
| 模型名称 | 在服务商控制台复制模型 ID |
| API Key | 你自己的 Key |

填好后点「测试连接」验证。

### 其他命令

```powershell
npm run build          # 生产构建
npm start              # 生产模式运行
npm run lint           # 代码检查
npm test               # 构建 + 自动化测试
```

## 数据与隐私

- 项目数据和导入的原文件保存在**浏览器 IndexedDB**，不会上传到本项目的服务器。
- 执行 AI 分析时，用户勾选章节的文字会发送到**其自行配置的模型服务商**。
- API Key 默认只保存在浏览器会话中，关闭浏览器后需重新填写。
- 本地模型代理仅接受 HTTPS 地址；`localhost` 与 `127.0.0.1` 允许使用 HTTP。

## 已知限制

1. **依赖文字层**：PDF 必须是文字版（扫描件需先 OCR）。以图片形式排版的章节标题无法识别。
2. **章节识别基于标题的文字形态**：不在固定词表内、又无编号的标题可能漏检；目录使用罗马数字或无编号时，目录判定会退化为「单页命中数」判断。
3. **同名章节会合并**：若模组中确实存在两个同名章节，会被去重成一条，需要手动补回。
4. **首个标题前的内容**会归入自动生成的「开篇」章节（标题为通用名，可手动修改），以保证这部分内容不被静默丢弃。
5. **模型输出质量取决于文档质量**：章节划分不准会直接影响检索命中率，进而影响分析结果。
