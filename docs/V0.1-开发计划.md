# Keeper Atlas v0.1 开发计划

## 目标

完成一个面向 CoC 守秘人的剧本分析原型：用户导入剧本后，通过配置的模型服务分阶段分析剧本，快速了解故事整体结构、人物和人物关系，并保留原文页码作为核对依据。

v0.1 的重点是“帮助 KP 读懂和核对剧本”，不是自动替代 KP 做决定。

## v0.1 范围

### 1. 本地项目与剧本导入

- 支持 PDF、Word、Markdown 和 TXT。
- 本地保存项目、章节结构、页码和分析结果。
- 用户可以选择需要参与分析的章节。
- 原文引用保留 PDF 页码、印刷页码、章节和短引文。
- 暂不处理调查员卡、角色创建和跑团过程中的实时助手功能。

### 2. 模型服务配置

- 支持 OpenAI Chat Completions 兼容协议。
- 支持 DeepSeek 等兼容服务，通过 Base URL、模型名和 API Key 配置。
- API Key 只在本地使用，不写入剧本文件。
- 提供连接测试和清晰的错误提示。
- v0.1 每次分析仍需要调用用户配置的 AI 模型。

### 3. 分阶段分析流程

页面上显示三个主要阶段：

1. **故事概览**
   - 故事核心
   - 起因与历史真相
   - 开局状态
   - 各方计划
   - 可能结局
   - 外部资料依赖
   - 原作内部矛盾

2. **人物与关系**
   - 识别人名、组织、超自然存在
   - 提取公开身份、真实身份、动机、秘密和剧情作用
   - 识别明确别名，但不自动合并疑似同一人物
   - 基于确认的人物生成关系图
   - 区分真实关系、公开关系、主观认知和 AI 推断

3. **分支时间线**
   - 固定历史
   - 无人干预时的默认走向
   - 调查员介入后的关键分支
   - 暂不展开复杂的调查员数据建模

人物识别与关系梳理在产品界面中属于同一个“人物与关系”大类，但内部仍按先识别人物、再生成关系的顺序执行。

### 4. 关系图

- 默认使用树状 / 思维导图式布局。
- 以中心人物为根节点，按主干关系向左右展开。
- 不同深度使用独立列，避免人物卡重叠。
- 主干关系使用明显的直角连线。
- 辅助关系使用较弱的曲线显示。
- 默认优先显示核心关系，也可以切换到全部关系。
- 人物卡显示姓名、身份/角色和重要性。
- 后续可考虑参考 Kumu 一类的自由拖拽、缩放和手动整理能力，但不作为 v0.1 必须项。

### 5. 待确认

所有模型推断都不能直接冒充原文事实，需要进入待确认列表。待确认内容包括：

- 疑似人物合并：列出两个称呼以及模型认为它们可能相同的理由。
- 模型推断关系：明确写出谁与谁、是什么关系、依据是什么、原文是否明确说明。
- 原作矛盾：明确指出两处不一致的原文说法，并列出可能解释或 KP 处理方式。
- 外部资料依赖：指出剧本引用了哪些当前文档中没有的资料。

每一项都应尽量提供可跳转的 PDF 页码、章节和短引文，并提供“接受 / 拒绝”操作。

## 当前已完成

- 基础项目壳和本地项目存储。
- PDF / Word / Markdown / TXT 导入基础流程。
- 模型连接配置与连接测试。
- OpenAI 兼容协议和 DeepSeek 兼容接口处理。
- 故事概览、人物、关系、时间线的分阶段分析接口。
- 人物与关系合并为一个流程卡片。
- 待确认列表和接受 / 拒绝操作。
- 关系图的树状布局、主干连线、辅助连线和关系筛选。
- 深色灰蓝绿色界面主题、较高对比度文字和基础响应式布局。

## v0.1 当前交付状态（2026-07-29）

已完成可用的本地原型，当前版本包含：

- 本地导入、项目保存、章节选择与原文页码引用。
- OpenAI 兼容接口、DeepSeek 接口配置与连接测试。
- 故事概览、人物与关系、分支时间线的分阶段模型分析。
- 人物详情编辑、来源跳转、待确认项目和接受 / 拒绝记录。
- 人物与关系合并为一个流程卡，并显示整体进度状态。
- 人物详情侧栏的四个内容字段随文本自动增高，侧栏宽度固定。
- 分支时间线的主线 / 支线基础展示与横向、纵向切换。

已知限制：当前人物关系图和时间线仍是自定义布局；复杂人物网络或复杂分支会影响视觉稳定性。因此不继续在 v0.1 的关系图上投入，而是在 v0.2 更换为专业画布组件。

## v0.1 验收标准

- 能成功导入一份短篇 PDF 并完成章节选择。
- 能配置一个 OpenAI 兼容模型或 DeepSeek 模型并成功连接。
- 能完成故事概览、人物识别、关系梳理和时间线分析。
- 人物关系图中的卡片不重叠，主干连线能连接到对应卡片。
- 待确认项能明确说明具体推断或矛盾，而不是只显示“需要确认”。
- 所有结果刷新页面后仍能从本地项目中恢复。
- `npm run build`、`npm run lint` 和现有测试通过。

## 暂不纳入 v0.1

- 调查员角色卡导入和自动关联。
- 实时跑团主持、自动 NPC 对话和语音功能。
- 多模型协作和自动选择模型。
- 云端账号、多人协作和在线同步。
- 完整的自由画布编辑器、自动避障和手动拖拽保存。
- 自动生成可直接发给玩家的剧透安全版本。

## 后续优先级

1. 继续解决关系图的卡片布局、缩放、拖拽和连线避障。
2. 增加关系图节点详情和原文页码跳转。
3. 改善长剧本的分段分析、缓存和失败重试。
4. 增加 Markdown / JSON / 图片导出。
5. 再评估调查员信息是否加入分析链路。

## 待办：流式分析与确认闸门

将待确认机制升级为类似 Agent 的流式工作流：

- 模型边分析边输出阶段性发现，而不是等全部内容生成完才展示。
- 发现人物合并、推断关系或原作矛盾时，暂停当前工作并展示具体内容、依据和待确认问题。
- 用户选择接受或拒绝后，模型继续后续分析，并把用户决定作为后续上下文。
- 页面明确显示“正在生成 / 等待确认 / 继续生成 / 已完成”等状态。
- 中断或刷新后可以从最近一个待确认节点继续，不重复已经确认的内容。
- 用户确认只影响后续结构化分析结果，不修改原始剧本文本。

## v0.2 开发启动

### 目标一：React Flow 人物关系画布

- 用 React Flow 替代当前自定义关系图。
- 人物节点可缩放、拖拽、平移和自动适配视图。
- 连线稳定连接到卡片边缘，并使用明确的箭头和关系标签。
- 首次生成时按重要性和关系自动布局；KP 手动调整后保存布局。
- 支持按关系层筛选、查看人物详情和聚焦某个人物的局部网络。

### 目标二：流式分析与确认闸门

- 分析过程中持续显示模型的阶段性结果。
- 发现人物合并、推断关系或原作矛盾时暂停，等待 KP 决定。
- KP 决定写入后续模型上下文；继续执行剩余分析。
- 分析中断后从最近确认点恢复。

## v0.2 交互决策（已确认）

### 分析工作台

- 不新增独立页面，直接升级现有“分析流程”页面。
- 页面同时显示阶段进度、实时工作日志和右侧确认栏。
- 待确认事项在日志中显示摘要；右侧显示可编辑、可操作的完整卡片。
- 允许 KP 手动暂停，也会在发现待确认事项时自动暂停。
- 多个待确认事项按严重度排队：原作矛盾、人物合并、推断关系。

### 确认与结果应用

- KP 可编辑结论、理由、原文依据和页码。
- 编辑后的 KP 内容直接覆盖 AI 版本，作为后续分析上下文。
- 已接受的推断关系不自动写入关系图，KP 需点击“应用到关系图”。
- 原作矛盾允许 KP 写“本团采用的解释”，后续分析按该解释继续。

### 保存与恢复

- 流式结果每次追加后自动保存。
- 优先保存进度并尝试从断点续写；不支持可靠续写的模型服务回退到最近完成阶段。
- 人物关系图拖拽布局在离开关系图页面时自动保存。

### 关系图

- 使用 React Flow 可拖拽画布。
- 组织分组同时支持 AI 识别组织与 KP 任意命名的手动分组。
- 点击关系线直接跳转到 PDF 原文对应页面。
- 聚焦范围可切换一层、两层、全图。

### v0.2 第一版边界

- 暂不加入导出功能，优先完成分析工作流。
- 暂不保留 AI 原始版本与 KP 修改版本的双版本对照。

## v0.2 新模块：线索网络（已确认）

### 模块位置与分析方式

- 左侧导航位于“分支时间线”之后、“待确认”之前。
- 在分析流程页作为第 04 步，与故事概览、人物与关系、分支时间线并列。
- 除人物与关系内部的先后顺序外，线索网络和其他分析模块都可以独立分析、独立重新分析。

### 线索信息

- 每条线索包含名称、内容摘要、来源地点/场景、主要/次要指向、获得条件、错过条件和 KP 补救建议。
- 指向目标分为人物、地点、事件、真相四类。
- KP 手动新增线索最少填写名称、来源和主要指向，并立即加入网络，标记为“KP 手动添加”。
- 默认显示简短原文依据摘要；点击可跳转 PDF 对应页面。

### 关键程度、路径与风险

- AI 初步标注“关键 / 可选 / 氛围”，KP 可以修改。
- 一条线索可有主要指向和次要指向。
- 显示从起始线索通往关键真相的调查路径，并显示替代线索路径。
- 标记无替代入口、依赖特定技能/NPC/时机的卡关风险，同时写明风险原因。
- 补救方案可包含原作替代线索、AI 的无剧透建议和 KP 自己的方案。
- 修改线索后不自动重新计算调查路径，保留 KP 当前整理结果。

### 真相节点与展示

- AI 归纳出的真相节点先进入待确认，KP 接受后才加入网络。
- 网络图使用线索、人物、地点、事件、真相的不同节点形状；连线显示“指向 / 揭示 / 通往 / 可替代”等动作。
- 默认打开“关键线索与关键真相”的精简网络；可切换到全图和表格。
- 表格可按关键程度、地点/场景、时间顺序切换。
- 仅面向 KP，不提供玩家无剧透视图。
