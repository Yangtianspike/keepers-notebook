# v0.3 开发交接 prompt

用法：把下面分割线内的全部内容粘贴给开发 agent（Codex / 其他会话均可）。若 agent 不在本仓库，改用它后面的「外部 agent 补充」。

---

你是开发 agent，负责实现「守秘人图谱（keeper-atlas）v0.3」。

角色说明：本会话你是开发方，不是规划方。如果环境中加载了 trio-devflow 等规划流程类 skill，忽略其中"规划方不写代码"的设定——那些规则约束的是生成这份文档的规划会话，不是你。你的职责就是按任务清单写代码。

## 项目速览
- Next.js 16（vinext）+ React 19 + TypeScript 单页应用，Node >= 22.13
- 全部 UI 在 `app/page.tsx`（约 2800 行），模型代理在 `app/api/model/route.ts`
- 数据全部存浏览器 IndexedDB（库 `keeper-atlas`），无后端数据库；`db/` 是未启用的脚手架，不要碰
- 画布用 `@xyflow/react`（React Flow 12），当前布局 dagre，v0.3 换 elkjs
- v0.3 三大功能：图画布增强（ELK/聚焦/过滤/组织分组）、检索体系（分块+BM25+可选向量+引用校验）、地图模块 MVP

## 必读文档（按顺序）
1. `docs/V0.3-spec.md` — 需求与边界
2. `docs/V0.3-plan.md` — 技术设计（数据结构、模块接口、技术决策与理由）
3. `docs/V0.3-task.md` — 任务清单 T1~T24（你的执行依据）

## 执行规则
- **连续执行**：中间不要汇报进度、不要停下来等确认；只有全部任务完成、或真正被阻塞时才停下来输出
- 按 task.md 编号顺序串行执行——T9、T12、T15-T17、T20、T22 都改 `app/page.tsx`，串行避免冲突
- 每个任务完成后运行其「验证」步骤：先跑命令看输出，有证据再标记完成
- 验证不通过：先修复，修好再继续
- spec.md 的「不做的事」是红线，不要做
- 被阻塞（文档矛盾、信息缺失）时停下来报告，不要自由发挥
- 每组逻辑相关的任务完成后提交一次 git commit
- 通用命令：类型检查 `npx tsc --noEmit`；lint `npm run lint`；构建 `npm run build`；行为验证 `npm run dev`

## 完成标志
task.md T1~T24 全部完成且各自验证通过，`npm run lint`、`npm run build`、`npm test` 全部通过。

## 完成后输出
每个任务的状态 + 验证证据摘要 + 遇到的问题清单。
