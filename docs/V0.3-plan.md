# 守秘人图谱 v0.3 Plan

对应 spec：`docs/V0.3-spec.md`（已批准）。

## 架构概览

v0.3 在现有单页应用（`app/page.tsx` + `app/api/model/route.ts` 代理 + IndexedDB）之上增加四个新模块，全部以**纯函数 lib 模块**形式落地，`page.tsx` 只做接线，避免本已 2800 行的文件继续膨胀：

1. **graph-layout**（`lib/graph-layout.ts`）：ELK 分层布局、邻域聚焦、可见性过滤的纯函数库，供人物关系图与线索网络图两个画布调用。
2. **retrieval**（`lib/retrieval.ts`）：剧本分块 + BM25 关键词检索 + RRF 混合排序，分析流程的注入数据源。
3. **embedding**（`lib/embedding.ts` + 代理路由新 action）：协议能力探测、向量存取、向量召回。
4. **quote-check**（`lib/quote-check.ts`）：模型返回的 SourceRef.quote 对原文的模糊校验。
5. **atlas-map**（`app/components/atlas-map.tsx`）：地图管理、打点、地点卡聚合视图，是项目里第一个独立于 `page.tsx` 的视图组件。

数据继续全部存浏览器 IndexedDB（库 `keeper-atlas`），版本从 1 升到 2，新增两个对象仓库；`db/`（drizzle/D1 脚手架）继续不使用。

export type ProjectAnalysis = {
  // ...现有字段不变

### ReviewItem 扩展（F7、F13）

`type` 增加两个枚举值：

```ts
type: "merge" | "relation" | "event" | "conflict" | "external" | "quote" | "place";
```

- `quote`：引用校验未命中，severity 固定 `warning`，description 记录未命中的 quote。
- `place`：AI 提名地点，配套 `proposal` 新增 `{ kind: "placeConfirm"; placeId: string }`。

## 模块设计

### graph-layout（`lib/graph-layout.ts`，新建）

**职责：** 画布的布局、聚焦、过滤，全部为无副作用纯函数，三个画布（关系图、线索图；时间线本期不动）共用。
**对外接口：**

```ts
layoutWithElk(input: ElkGraphInput): Promise<Map<string, { x: number; y: number }>>
// ElkGraphInput = { nodes: {id,width,height,parentId?}[], edges: {id,source,target}[] }
// parentId 用于 ELK compound 分组（F4 组织容器）

computeNeighborhood(focusId: string, edges: {source:string,target:string}[], depth: 1 | 2): Set<string>
// BFS 邻域节点集合；depth 外即不可见

filterRelationshipView(people, relations, opts: {
  layers?: Relation["layer"][];       // F3：truth/public/belief
  provenance?: Provenance[];          // F3：KP已知/公开/AI推断 对应 keeper/source/inference
  focusId?: string; depth?: 1 | 2;    // F2
  groupByOrg?: boolean;               // F4
}): { visiblePeople: Person[]; visibleRelations: Relation[] }

filterClueView(clues, opts: {
  importance?: Clue["importance"][];  // F3：key/secondary/other
  targetTypes?: ClueTarget["type"][]; // F3：person/place/event/truth
  focusId?: string; depth?: 1 | 2;
}): Clue[]
```

**依赖：** `elkjs`（新增依赖）、`lib/types.ts`。

### retrieval（`lib/retrieval.ts`，新建）

**职责：** 分块索引的构建与失效检测、BM25 检索、向量/关键词混合排序。
**对外接口：**

```ts
buildChunks(pages: DocumentPage[], projectId: string): TextChunk[]
// 按页拼接，约 500 字/块、重叠约 50 字；块边界记录页码区间。
// 数据源是 pages 而非 documentText——页码区间天然可得，不用回扫 [[PDF_PAGE:N]]。

ensureChunkIndex(project: Project): Promise<TextChunk[]>
// textHash 比对：一致返回缓存（IndexedDB chunks 仓库），不一致重建并写回（N4）。

bm25Search(chunks: TextChunk[], query: string, k: number): ScoredChunk[]
// 中文按二字滑窗（bigram）切词，标准 BM25（k1=1.5, b=0.75）。

hybridSearch(project: Project, query: string, k: number): Promise<ScoredChunk[]>
// 有向量命名空间 → BM25 TopK 与向量 TopK 做 RRF 融合（常数 60）；
// 无 → 退化为纯 BM25。对外永远一个入口，调用方不关心能力等级。

stageQuery(stage: AnalysisStage, analysis: ProjectAnalysis): string
// 各阶段的检索查询词：固定关键词 + 已有上下文（如 relations 阶段附带人物名单）。
```

**依赖：** `lib/storage.ts`、`lib/embedding.ts`（向量召回，可选）。

### embedding（`lib/embedding.ts`，新建）

**职责：** 能力探测结果的应用、向量索引构建、向量召回。全部浏览器端逻辑。
**对外接口：**

```ts
probeEmbedding(baseUrl: string, apiKey: string): Promise<EmbeddingCapability | null>
// 调用代理 action:"embedTest"，成功返回能力声明，任何失败（超时/404/协议不支持）返回 null。

ensureVectorIndex(project: Project, cap: EmbeddingCapability, apiKey: string): Promise<void>
// 命名空间 = embedModel（含维度）。chunks 无该命名空间向量时，
// 分批调用代理 action:"embed" 向量化并写入 vectors 仓库。

vectorSearch(projectId: string, cap: EmbeddingCapability, queryVector: number[], k: number): Promise<ScoredChunk[]>
// 余弦相似度，在对应命名空间内检索。
```

**依赖：** `lib/storage.ts`、代理路由。

### quote-check（`lib/quote-check.ts`，新建）

**职责：** SourceRef 引用校验（F7）。
**对外接口：**

```ts
verifySourceRefs(data: unknown, pages: DocumentPage[]): QuoteIssue[]
// 遍历 stage 输出中所有 sources，每条 quote 规范化（去空白/标点/大小写）后，
// 在其声明页 ±1 页的规范化原文上做子串匹配，失败再做全文滑窗相似度（阈值 0.85）。
// QuoteIssue = { path: string; quote: string; page: number }，供调用方生成 ReviewItem(type:"quote")。
```

**依赖：** `lib/types.ts`。

### atlas-map（`app/components/atlas-map.tsx`，新建）

**职责：** 地图模块 MVP 的全部 UI（F12~F16）：地图列表与上传、地图画布打点、地点列表、地点卡聚合。
**对外接口：**

```tsx
export function AtlasMapView(props: {
  project: Project;
  onUpdate: (project: Project) => void;
  onOpenSource: (source: SourceRef) => void;   // 复用现有 SourceModal 跳 PDF（F16）
  onOpenPlace?: (placeId: string) => void;
}): JSX.Element
```

- 图片以 Blob 存 IndexedDB `files` 仓库（复用现有 `saveSourceFile` 模式），`AtlasMap.imageKey` 记录 key。
- 打点交互：点击地图空白处 → 进入"放置地点"态 → 选地点落 marker；拖拽 marker 改位置。
- 地点卡聚合：指向该地点的线索（`ClueTarget.type==="place"` 且 id 匹配）+ 这些线索的其他指向（人物/事件/真相），点击可跳对应模块。
- 未打点地点显示在侧边列表，可拖入地图。

**依赖：** `lib/types.ts`、`lib/storage.ts`。

### 代理路由扩展（`app/api/model/route.ts`，修改）

- `action` 联合类型新增 `"embedTest" | "embed"`。
- `embedTest`：向 `${baseUrl}/embeddings` 发一条最小输入（`{"model": body.model ?? 默认探测名, "input": "test"}`）；成功则返回 `{ supported: true, model, dimensions }`（dimensions 从返回向量长度读）；任何失败返回 `{ supported: false }`，HTTP 200，不抛错（N2）。
- `embed`：接收 `{ texts: string[], model }`，透传 embeddings 接口，返回向量数组。
- 端点构造复用 `endpointFor` 的 HTTPS/localhost 校验，`/embeddings` 与 `/chat/completions` 同样规则。
- `analyze` 的 prompt 模板中 `<scenario>` 语义从"全文"改为"相关原文摘录"，文案相应调整。

### page.tsx 接线（修改）

- 三个 stage 相关函数接检索：`runStage` 中 `document.text` 从 `includedText()` 全文改为 `hybridSearch` TopN 块拼接（每块前置 `[[PDF_PAGE:N]]`）；检索失败或无索引时回退全文（安全网）。
- `runStage` 解析 payload 后调用 `verifySourceRefs`，未命中 quote 生成 `ReviewItem(type:"quote")`；clues 阶段后从 place targets 提名 Place 候选生成 `ReviewItem(type:"place")`，接受后建/合并 Place 并回填 `ClueTarget.id`。
- 关系图、线索图：布局换 `layoutWithElk`（保留 `savedLayout` 优先），加聚焦/过滤/分组工具条，线索图补 `onNodeDragStop` 持久化到 `clueLayout`；"重新布局"按钮显式触发 ELK，数据变更不再隐式重排（修掉 `useEffect` 重置行为）。
- people 阶段 prompt（`stageInstructions`）要求提取 `organization`。
- 设置页：保存时触发 `probeEmbedding`，徽章显示"向量检索可用（模型名）/ 仅关键词检索"（F10）。
- 导航新增"地图"视图（View 联合类型 + `AtlasMapView`）。
- 删除旧版 HTML 时间线死代码（L1027-1179，已被 early return 屏蔽）。

## 模块交互

**分析流程（检索注入 + 引用校验）：**

```
runStage(stage)
  → ensureChunkIndex(project)          // N4：文本变更则重建
  → hybridSearch(stageQuery(...))      // 有向量自动混合，无则 BM25
  → document.text = TopN 块拼接        // 失败回退 includedText() 全文
  → POST /api/model { action:"analyze" }
  → parseModelJson(流式累积)
  → verifySourceRefs(data, pages)      // F7
  → 未命中 → ReviewItem(type:"quote") 进确认队列
  → clues 阶段额外：place targets → ReviewItem(type:"place") 提名
```

**设置保存（能力探测）：**

```
SettingsView 保存
  → 本地保存 ModelConfig（同现有）
  → POST /api/model { action:"embedTest" }（后台，不阻塞保存）
  → 成功 → ModelConfig.capabilities.embedding = { model, dimensions }
        → 徽章"向量检索可用"→ 后台 ensureVectorIndex
  → 失败 → capabilities.embedding 删除 → 徽章"仅关键词检索"
```

**地点卡聚合：**

```
点击地图 marker / 地点列表项
  → Place 详情卡
  → 聚合：clues.filter(target 含该 placeId)
       + 这些 clues 的其他 targets（人物/事件/真相）
  → 点击线索/人物跳对应模块；点击依据 onOpenSource 跳 PDF
```

## 技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 布局引擎 | elkjs `elk.layered` 替换 dagre（仅关系图/线索图） | spec 已定；ELK compound nodes 原生支持分组容器（F4），dagre 做不到；时间线不在 spec 范围，保持 dagre 不动 |
| 分组实现 | ELK compound（`children`/`parentId`）+ React Flow 子流程节点 | 不自绘容器，布局与折叠交给成熟机制 |
| 隐式重排 | 禁止；`savedLayout` 优先，重布局仅按钮触发 | F1/AC1：KP 手工整理的结果不能被数据变更冲掉 |
| 分块数据源 | `Project.pages` 而非 `documentText` | 页码区间天然可得，避免正则回扫页码标记 |
| 中文检索分词 | 二字滑窗（bigram） | 中文无词边界，bigram 对 BM25 足够且零依赖 |
| BM25 | 自实现（约百行） | 千级块规模无性能压力，不引依赖 |
| 混合排序 | RRF（Reciprocal Rank Fusion，k=60） | 不需要跨体系调分，比加权分数稳定 |
| 向量存储 | IndexedDB `vectors` 仓库，key 含 `embedModel`（模型+维度） | F11 命名空间要求；换模型即换 key，旧向量自然隔离 |
| 向量构建时机 | 探测成功后后台构建，不阻塞保存 | N2：embedding 是增强不是依赖 |
| 能力探测 | 代理路由 `embedTest` action，失败也返回 200 | 复用 HTTPS 校验；N2 要求探测失败不报错 |
| 引用校验 | 规范化 + 声明页±1 子串 + 全文滑窗 0.85 阈值 | 纯本地零成本；先窄后宽减少误报 |
| 检索失败兜底 | 回退现有全文注入 | 检索是优化不是单点，任何异常都不能让分析跑不了 |
| 地图图片 | Blob 存 `files` 仓库（复用 `saveSourceFile`） | 与原始文件同机制，不新增存储范式 |
| 地点-人物/事件关联 | 经线索间接聚合，不建直接外键 | YAGNI：现有 `ClueTarget` 已能表达关联，地点卡要的就是这个视图 |
| 新 UI 代码位置 | 地图进 `app/components/`，lib 逻辑全部独立文件 | `page.tsx` 已 2810 行，新模块不再膨胀它 |
| `db/`（drizzle） | 继续不使用 | 空脚手架，本地优先路线不变 |
| 旧 HTML 时间线死代码 | 删除 | 已被 early return 屏蔽，留着只会误导 |
