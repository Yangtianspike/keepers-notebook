# 守秘人图谱 v0.3 Spec

## 背景

v0.2 交付了人物关系画布、流式分析与 KP 确认闸门、线索网络模块，但留下三个待解决的问题：

1. **图画布可读性不足。** v0.2 的 React Flow 关系图使用现有简单布局，节点增多后难以阅读；组织分组、人物聚焦（一层/两层/全图）在 v0.2 验收时被明确推迟。线索网络画布同样缺少聚焦与过滤能力。
2. **分析 token 消耗高、引用无法校验。** 当前分析流程每个阶段都把剧本全文塞进 prompt，token 消耗随剧本长度线性增长；模型返回的"原文依据"是否真实存在于原文，系统无法校验，KP 只能逐条人工核对。
3. **地点没有实体化。** v0.2 边界明确"暂不做独立地点与场景分析模块"，线索中的地点仅以 AI 识别的名称字符串记录，无法聚合"这个地点相关的所有线索/人物/事件"，也没有地图上的直观呈现。

v0.3 同时推进三个方向：图画布增强（ELK 自动布局 + 聚焦/过滤/分组）、检索体系（本地分块索引 + 能力自适应的向量检索 + 引用校验）、地图模块 MVP（地点实体化 + 地图打点）。

## 目标

- 让大规模关系图/线索图可读：自动布局 + 聚焦 + 过滤 + 分组。
- 降低分析 token 消耗：各分析阶段从"全文注入"改为"检索相关原文块注入"。
- 让引用可校验：模型返回的每条原文依据必须在原文中真实命中，未命中的自动进入待确认。
- 协议层能力自适应：embedding 是可选增强而非必选依赖，任何 OpenAI 兼容协议下系统都能工作。
- 地点升格为实体：聚合地点相关的线索/人物/事件，支持在地图上打点查看。

## 功能需求

### 图画布增强

- F1: 人物关系图与线索网络图引入 ELK 分层自动布局；KP 手动拖拽调整的节点位置优先于自动布局，重新自动布局需 KP 主动触发，不被数据变更隐式触发。
- F2: 提供节点聚焦模式：选中一个节点后可切换显示其一层关系、两层关系或全图。
- F3: 提供过滤能力：人物关系图可按关系来源类型（KP 已知 / 公开 / AI 推断）过滤；线索网络图可按关键程度（关键 / 次要 / 其他）和指向目标类型（人物 / 地点 / 事件 / 真相）过滤。
- F4: 人物关系图支持按组织分组：同一组织的人物在画布上聚合为分组容器，容器可展开 / 折叠。

### 检索体系

- F5: 剧本文本建立本地分块索引（约 500 字/块、相邻块重叠约 50 字），每块记录页码区间（基于原文中的页码标记），索引数据存于浏览器本地。
- F6: 提供关键词检索（BM25）；分析流程各阶段从全文注入改为注入检索出的 TopN 相关块，检索结果携带页码，直接作为合法的来源引用。
- F7: 引用校验：模型返回的每条原文依据必须在原文中模糊匹配命中；未命中的依据被标记并自动进入待确认队列，KP 确认前不作为有效结论。
- F8: 协议层能力抽象：模型配置从"仅 baseUrl + model"扩展为带能力声明的结构（chat 能力 + 可选 embedding 能力及各自模型名），作为后续多协议扩充的地基。
- F9: embedding 自动探测：保存模型配置时在后台探测一次该协议是否支持向量化，结果（是否支持 / 可用模型 / 向量维度）缓存于本地；探测成功则自动启用向量检索并与关键词检索混合排序，失败则静默停留在关键词检索，分析与保存流程不受影响。
- F10: 设置页显示检索能力徽章（"向量检索可用 / 仅关键词检索"），探测结果对用户可见但无需任何操作。
- F11: 向量索引按"模型 + 维度"分命名空间存储；切换 embedding 模型或更换协议导致维度变化时，旧向量自动作废，不混入新检索结果。

### 地图模块（MVP）

- F12: 地图管理：KP 可上传地图图片（支持多张）、命名、删除；图片数据存于浏览器本地。
- F13: 地点实体：地点升格为独立实体，包含名称、简介、原文依据（页码）；AI 分析可提名地点进入待确认队列，KP 可手动新增 / 编辑 / 合并地点。
- F14: 地图打点：KP 可将地点标注到某张地图的坐标位置上；已打点与未打点的地点在界面上均可辨识。
- F15: 地点卡聚合：点击地图上的点或地点列表项，打开地点卡，聚合显示该地点关联的线索、人物、事件，并可跳转到对应详情。
- F16: 地点的原文依据支持点击跳转到 PDF 对应页。

## 非功能需求

- N1: 隐私等级不降低。所有分块索引与向量数据存于浏览器本地；使用 API embedding 时不向分析所用服务商之外发送任何数据；不引入新的外部服务依赖。
- N2: 协议兼容兜底。检索体系在任何 OpenAI 兼容 chat 协议下可用（至少关键词检索路径）；embedding 探测失败、超时或协议不支持时，分析、保存、检索流程均不报错。
- N3: 性能。剧本规模（数百页、千级分块）下单次本地检索响应在 200ms 内；画布在 200 节点规模内拖拽、缩放、聚焦切换流畅。
- N4: 索引一致性。剧本重新导入或文本更新后，分块索引与向量索引随之重建或明确提示失效，不静默使用过期索引。

## 不做的事

- 浏览器本地 embedding（transformers.js 跑本地模型）→ v0.4，配合本地模型全离线链路再做。
- 独立 embedding 端点配置（与 chat 不同的服务商）→ 随协议扩充时一起做。
- Anthropic / Gemini 等非 OpenAI 兼容协议的适配 → 后续版本；v0.3 只做能力抽象这层地基。
- 地图的绘制 / 编辑功能（画区域、路径、自定义标注）→ 后续版本；v0.3 只有打点和地点卡。
- 玩家无剧透视图 → 保持 v0.2 边界。
- 导出功能 → 保持 v0.2 边界。

## 验收标准

- AC1（F1）：两张图均呈现 ELK 分层自动布局；手动拖拽节点后刷新页面，位置保持；数据变更不会隐式重排 KP 已调整的位置。
- AC2（F2）：选中任一节点切换一层 / 两层 / 全图，画布只显示对应范围的节点与边。
- AC3（F3）：切换过滤条件，画布即时增减对应节点与边，两种图的过滤各自生效。
- AC4（F4）：含多组织的剧本中，人物按组织聚合为容器，容器可折叠 / 展开。
- AC5（F5、F6）：分析流程运行时，发给模型的 prompt 包含检索出的相关原文块（带页码）而非剧本全文，token 消耗相比全文注入显著下降。
- AC6（F7）：模型返回一条原文中不存在的虚假依据时，该依据被标记并进入待确认队列；真实依据正常通过，不产生误报阻塞。
- AC7（F8、F9）：使用支持 embedding 的协议配置保存后，索引自动向量化并启用混合检索；使用不支持 embedding 的协议（如 Kimi）时，分析与检索正常走关键词路径，全程无报错。
- AC8（F10）：设置页在上述两种协议配置下分别显示"向量检索可用"与"仅关键词检索"徽章。
- AC9（F11）：切换 embedding 模型后，旧维度向量不出现在新检索结果中。
- AC10（F12~F16）：上传地图 → 建立地点（AI 提名经确认或手动新增）→ 打点 → 打开地点卡看到聚合的线索 / 人物 / 事件 → 点击依据跳转 PDF 对应页，全流程走通。
