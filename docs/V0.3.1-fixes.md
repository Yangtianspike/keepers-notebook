## F2: 端点不在人物列表的边被静默丢弃

**文件**：`app/page.tsx`（约 3389–3398 行，validPeople 过滤处）
**现状**：sourceId/targetId 不在人物列表的边直接丢弃，无记录、无提示。
**问题**：高发场景——刺杀目标是"调查员"（PC 不在 people 阶段产出列表里）；模型用了名称变体导致 id 不匹配。用户完全不知道丢了东西。
**改法**：不静默丢弃。统计被过滤的边数量，写入 activityLog，并在关系图面板显示提示"N 条关系因端点未识别被搁置"。完整兜底（内置调查员节点、名称模糊匹配修正、进待确认队列、id 锚定）属 v0.4，本轮只做**可见性**。
**验证**：构造一条端点不在人物列表的关系 → 提示出现且数量正确；正常项目（无丢弃）不显示提示。

## F3: 画布 18 人硬截断无提示

**文件**：`app/page.tsx`（约 1128 行，`.slice(0, 18)`）
**现状**：超过 18 人时次要人物节点消失，相关边一并被滤掉，界面无任何提示，KP 以为图是全的。
**改法**：保留截断（性能考虑），但超出时在关系图面板显示"还有 N 人未显示"提示。
**验证**：超过 18 人的项目 → 提示出现且数字正确；不超过时不显示。

## F4: relations 阶段 max_tokens 偏低

**文件**：`app/api/model/route.ts`（约 39–43 行，max_tokens 档位表）
**现状**：relations 走默认档 12000，people/timeline/clues 是 16000。人物多时单轮长 JSON 易截断，`finish_reason=length` 时整个关系阶段失败——不是漏一条，是全丢。
**改法**：relations 档位提到 16000，与其他阶段对齐。
**验证**：代码审查确认档位；有长剧本时跑关系阶段，日志不再出现 `finish_reason=length`。

## F5: relations 检索词缺敌对/意图动词

**文件**：`lib/retrieval.ts`（约 163 行，relations 阶段 query）
**现状**：query 为 `人物 关系 联盟 敌对 秘密 + 人名拼接`。BM25 是纯词面匹配，"他决心在满月之夜动手除掉那个女孩"这类描写无任何关键词命中，进不了 Top 12。
**改法**：query 扩充敌对/意图动词：`刺杀 谋杀 阴谋 计划 意图 勒索 跟踪 背叛 献祭 威胁 监视 仇恨 保护 利用`。
**验证**：用含刺杀/阴谋情节的剧本跑检索，确认相关块被召回（可在检索函数出口打印或断点查看 Top 块内容）。

## F6: 拖拽节点后刷新页面位置丢失

**文件**：`app/page.tsx`（关系图布局相关）
**现状**：同一会话内手动拖拽节点后，重跑分析位置不变（内存态正常）；但**刷新页面**后，自定义位置丢失，回到初始布局。
**问题**：IndexedDB 恢复时，saved layout 可能被首次布局（ELK 默认布局）覆盖，或恢复路径本身存在错误。
**改法**：开发 agent 先定位断点——检查 `hydrateProject` 恢复 `relationshipLayout`/`clueLayout` 的流程，以及 React Flow 首次渲染时是否被 `relationshipInitialized` 或布局计算覆盖。修复后确保：刷新时先从 IndexedDB 恢复 layout，若已有保存位置则不再重算默认布局。
**验证**：
1. 拖几个节点到新位置
2. 刷新页面（F5）
3. 节点位置与刷新前一致（而非回到默认布局）

## F7: 聚焦一层/两层选项无法选择

**文件**：`app/page.tsx`（关系图/线索图聚焦 UI 处）
**现状**："一层""两层"等聚焦模式选项在 UI 上显示但无法点击/选择，聚焦功能未按预期工作。
**问题**：UI 交互状态绑定错误，或选项的 onChange 事件未正确触发聚焦函数。
**改法**：开发 agent 定位聚焦选项组件（Radio/Select 或类似）的事件绑定，修复选择状态变更与实际聚焦逻辑（`filterRelationshipView` / `filterClueView`）的关联。
**验证**：点击"一层"→画布只显示选中节点及其 1 跳邻居；点击"两层"→显示 2 跳邻居；切"全图"→全部恢复。
