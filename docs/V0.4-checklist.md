## 十一、端到端场景

### 场景 1：完整新流程（需真实 LLM API Key + 测试剧本）

1. 导入剧本 PDF → 设置页选"实时确认"模式（Tier 1，DeepSeek）→ 跑分析
2. people 阶段 → 模型遇到冲突立即暂停弹出确认弹窗 → KP 裁决 → 模型继续生成 → 循环直到 people 阶段完成
3. relations 阶段 → 自动跑过 → timeline 自动跑过
4. clues 阶段 → 若有冲突暂停弹窗 → 处理完 → 分析完成
5. 进入人物页签 → 画廊显示所有人物 → 点击人物 → ego 视图显示关联人物（含 real/hidden 关系类型）→ 点击关联人物 → 导航正常 → 返回正常
6. 编辑人物 → 上传肖像 → 保存 → 画廊和 ego 均显示新肖像
7. 全 App 为暗色现代 UI 风格，无书卷残留

**预期结果**：全程无报错，实时确认生效（不是阶段后阻塞），UI 风格统一暗色。

### 场景 2：旧项目迁移

1. 打开一个 v0.3 旧项目（含 truth/public/belief 关系、人物、线索）
2. 检查人物页签 → 画廊正常显示人物
3. 检查关系 → 旧 truth/public 关系显示为 real，belief 显示为 hidden
4. 检查时间线/线索图 → 正常渲染
5. 检查分析日志 → 无迁移报错

**预期结果**：无报错，数据正确迁移，功能正常。

### 场景 3：恢复与重跑

1. 开始分析，在 people 阶段弹出第一个确认弹窗时刷新页面
2. 页面恢复后 → 自动弹出该阶段剩余待确认项
3. 处理完 → 自动继续后续阶段
4. 分析全部完成后 → 手动重跑 relations 阶段（单阶段重跑）→ 正常完成，不影响已确认的人物数据

**预期结果**：恢复正确，单阶段重跑不破坏已有数据。
