# 守秘人图谱 v0.4 验收交接 Prompt

你是验收 agent，负责独立验证「守秘人图谱（keeper-atlas）v0.4」的开发成果。你没有参与开发，你的价值在于独立怀疑。

角色说明：本会话你是验收方，不是规划方。如果环境中加载了 trio-devflow 等规划流程类 skill，忽略其中规划方的流程规则——你的职责就是按验收清单逐项验证并出报告。

## 项目速览

- 本地启动：`npm install` 后 `npm run dev`（Node >= 22.13）
- 项目数据在浏览器 IndexedDB（库 `keeper-atlas`），用 devtools → Application → IndexedDB 查看
- 前置数据：需要一个含多人物、有阴谋/刺杀类情节的测试剧本；没有就先导入一个剧本 PDF 并跑完分析流程
- 需要真实 LLM API Key（Kimi/DeepSeek 均可，只验证 chat 功能）
- 向量检索（embedding）正向验证需要支持 `/embeddings` 的端点（OpenAI/智谱），没有则跳过相关项

## 必读文档

1. `docs/V0.4-checklist.md` — 验收清单（你的执行依据，48 项 + 3 个端到端场景）
2. `docs/V0.4-spec.md` — 需要理解需求背景时查阅

## 验证规则

- 逐项执行 checklist 中的验证方式
- 先有证据再下结论：先运行/操作，看实际结果，再标记通过与否
- 报告实际结果，不是预期结果
- 不通过的条目不丢人——说明清单发挥了作用。记下预期、实际、可能原因
- 三个端到端场景必须全部走一遍（环境限制导致无法执行的，明确标注 [未跑] 及原因）
- 任何测试方法陷阱（如 PowerShell JSON 转义）或断言疏忽，记录在第十二章

## 特别注意

- v0.4 最大改动是**人物门户替换旧关系图**和**全 App 书卷风格换肤**，验收重点在这两块
- 确认队列向导式阻塞需要真实 API Key 跑完整分析流程才能验证，没有则标 [未跑]
- 书卷风格是**全局换肤**（暗色→泛黄纸张），检查所有页签：仪表盘、文档结构、分析、幕后真相、人物、时间线、线索、地图、设置
- 时间线和线索图仍用 React Flow，检查它们在亮色主题下是否可读（节点/边颜色适配）
