     - 删除 `provenance` 字段（仅 Relation 层面）

## T9: 协议适配层 + 分析流程实时确认改造

**文件**：`lib/model-adapter.ts`（新建）、`app/api/model/route.ts`（大改）、`app/page.tsx`（控制流改造）
**依赖**：T8
**注意**：这是 v0.4 补丁最大的改动，建议拆分多个 commit。

### T9.1: 协议适配层（`lib/model-adapter.ts`）

**步骤**：
1. 定义类型：`ConfirmMode = "tier1" | "tier2" | "tier3"`、`AskUserCall`、`ModelStreamEvent`
2. 定义 `ASK_USER_TOOL_DEF`（function calling 工具定义）
3. 定义 `ASK_USER_JSON_INSTRUCTION`（Tier 2 的 system prompt 指令，教模型输出 `<<ASK_USER>>{json}<</ASK_USER>>` 标记块）
4. 实现 `buildModelRequest(stage, confirmMode, previousMessages?)`：根据 tier 决定是否注入 tools 或 JSON 块指令
5. 实现 `parseStreamResponse(raw, confirmMode)`：检测 tool_call（Tier 1）或 JSON 块（Tier 2），返回 `ModelStreamEvent`
6. 实现 `buildContinueRequest(callId, answer, previousMessages, confirmMode)`：构建 continue 请求（Tier 1 用 tool role，Tier 2 用 user role）

**验证**：
- `npx tsc --noEmit` 零类型错误
- 代码审查：三档逻辑独立，互不干扰

### T9.2: route.ts 改造（服务端）

**步骤**：
1. `RequestBody` 新增字段：`confirmMode?: ConfirmMode`、`action: "analyze" | "continue"`、`callId?: string`、`previousMessages?: Message[]`
2. `action === "analyze"` 时：
   - 调用 `buildModelRequest(stage, confirmMode)` 构建请求
   - 调用模型 API
   - 调用 `parseStreamResponse(raw, confirmMode)` 解析响应
   - 如果返回 `ask_user` → 返回 `{ type: "ask_user", callId, question, options, context, previousMessages }`
   - 如果返回 `complete` → 返回 `{ type: "complete", data }`（现有逻辑）
3. `action === "continue"` 时：
   - 调用 `buildContinueRequest(callId, answer, previousMessages, confirmMode)` 构建请求
   - 调用模型 API
   - 调用 `parseStreamResponse` 解析 → 同上循环
4. Tier 3 保持现有逻辑不变（阶段后阻塞）

**验证**：
- 代码审查：三档请求构建和响应解析正确
- mock 测试：Tier 1 模型返回 tool_call → 正确解析为 ask_user 事件

### T9.3: page.tsx 控制流改造（客户端）

**步骤**：
1. 设置页新增"确认模式"选择器（tier1/tier2/tier3），存入 `project.settings.confirmMode`，默认 `tier1`
2. 修改 `runStage`：
   - 发送请求时带上 `confirmMode`
   - 收到 `{ type: "ask_user" }` → 设置 `stages[stage].status = "paused"`，保存 `pendingAskUserCall`，弹出 `ConfirmWizard`
   - 收到 `{ type: "complete" }` → 处理 data，继续下一阶段
3. `ConfirmWizard` 的 `onAccept` 回调：
   - 发送 `action: "continue"` 请求，带上 `callId`、`answer`、`previousMessages`
   - 收到响应 → 同上循环处理
4. 恢复逻辑：
   - 项目加载时检查 `stages[stage].status === "paused"` 且有 `pendingAskUserCall` → 自动弹出 ConfirmWizard 恢复
   - 如果 `paused` 但无 `pendingAskUserCall` → 走 Tier 3 的 reviewItems 逻辑
5. 阶段阻塞配置：
   ```typescript
   const PAUSE_STAGES: AnalysisStage[] = ["people", "clues"];
   ```
   （overview、relations、timeline 不阻塞）

**验证**：
- Tier 1 模式：跑 people 阶段 → 模型遇到冲突立即暂停弹窗 → KP 裁决后继续生成 → 不再是阶段跑完才弹窗
