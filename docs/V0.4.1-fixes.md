# 守秘人图谱 v0.4.1 修复任务单

对应：`docs/V0.4-handoff-dev.md`（v0.4 补丁）+ 用户验收反馈

## 背景

v0.4 补丁（T8/T9/T11/T12）已完成，用户验收发现 2 个 bug：

- **Bug A（严重）**：实时确认模式点击"接受并继续"后流程卡死，看起来没反应，但实际每次都在发请求。多次点击导致 20+ 个并发请求堆积，最终全部超时挂起。
- **Bug B（小）**：人物画廊的"搜索人物"输入框和"重要程度"下拉框看不见文字，线索网络也有同样问题。

---

## FA1: 修复实时确认并发请求堆积（Bug A）

**文件**：`app/page.tsx`（`continueRealtimeAnalysis` 函数，约第 3246 行）

**根因**：`continueRealtimeAnalysis` 中的 fetch 没有绑定 `AbortController.signal`，也没有在请求前 abort 上一次未完成的请求。用户多次点击"接受并继续"时，旧请求继续在飞，导致并发堆积。

**步骤**：
1. 在 `continueRealtimeAnalysis` 开头检查 `analysisAbortRef.current`：
   - 如果存在且未 aborted，先调用 `analysisAbortRef.current.abort()` 取消旧请求
   - 创建新的 `AbortController` 并赋值给 `analysisAbortRef.current`
2. fetch 调用加 `signal: analysisAbortRef.current.signal`
3. catch 中处理 `AbortError`，静默忽略（不显示错误）
4. finally 中如果当前 controller 已被 abort，不重置 `analysisAbortRef.current`

**验证**：
- 模拟快速连续点击 5 次"接受并继续" → devtools Network 面板只显示 1 个活跃请求（旧的被 cancel），不是 5 个
- 正常点一次接受 → 流程继续，无报错

## FA2: 修复输入框/下拉框不可见（Bug B）

**文件**：
- `app/components/person-gallery.tsx`
- `app/components/clue-network-view.tsx`（或实际线索图组件名）

**根因**：输入控件的背景色和文字色相同（典型情况：暗色主题下 `bg-[var(--bg-soft)]` + `text-[var(--text)]` 但控件没设文字色，或 className 引用了 v0.4 书卷变量如 `--parchment` 但 revert 后变量不存在）。

**步骤**：
1. 检查 `PersonGallery` 中的搜索 input 和重要程度 select 的 className
2. 检查线索图组件中的所有 input/select/textarea
3. 找到所有引用不存在 CSS 变量或颜色对比度为 0 的位置
4. 修正 className，使用 v0.3 暗色变量中**确实存在**的 token（如 `--text`、`--muted`、`--bg-soft`）
5. 确保 input/select 文字色与背景色有足够对比度（至少 WCAG AA）

**验证**：
- 打开人物画廊 → 搜索框可输入文字、下拉框可选中选项
- 打开线索网络 → 所有筛选控件可见可交互
- devtools 检查控件颜色：`color` 和 `background-color` 不同
