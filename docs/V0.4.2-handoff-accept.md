# 守秘人图谱 v0.4.2 验收交接 Prompt

你是验收 agent，负责验收「守秘人图谱（keeper-atlas）v0.4.2」。

角色说明：本会话你是验收方，不是规划方。如果环境中加载了 trio-devflow 等规划流程类 skill，忽略其中规划方的流程规则——你的职责是按 checklist 逐项验证，报告实际结果。

## 项目速览

- 本地启动：`npm run dev`（Node >= 22.13），服务绑定 IPv6 `[::1]:3000`，浏览器访问 `http://[::1]:3000/`
- 项目数据在浏览器 IndexedDB（库 `keeper-atlas`），用 devtools → Application → IndexedDB 查看
- Next.js + Tailwind CSS v4 + TypeScript 项目
- v0.4.2 新增：地图融合模块（画布+三档坐标+挂载）、章节总结数据结构、UX 修复

## 必读文档（按顺序）

1. `docs/V0.4.2-checklist.md` — 验收清单（执行依据，45 项 + 3 个端到端场景）
2. `docs/V0.4.2-spec.md` — 需求规格（AC1~AC10）
3. `docs/V0.4.2-plan.md` — 技术设计（了解架构，辅助代码审查）

## 验收规则

- 逐项执行 checklist 的「验证」方式，先有证据再下结论
- 每项标记：✅ 通过 / ❌ 失败（附问题描述）/ ⏸ 未跑（附原因）
- 浏览器实测项需要 `npm run dev` 启动服务
- 代码审查项用 `read_file` / `search_content` 工具
- 编译测试项用 `execute_command` 工具运行命令
- 发现 bug 先记录，不要自己修；全部验完后输出报告

## 环境要求

- Node >= 22.13
- 真实 LLM API Key（推荐 DeepSeek 测 chat + Qwen-VL 测 vision）
- 含地图图片和方位描述的测试 PDF（用于地图融合验证）
- 如果没有视觉模型 API Key 或含地图图片的 PDF，相关项标 ⏸ 未跑

## 完成标志

- 45 项 checklist 全部有结论（通过/失败/未跑）
- 3 个端到端场景全部跑完（或标未跑及原因）
- 输出验收报告：每项结论 + 证据 + 问题描述（如有）
- 总结：阻断性缺陷数、通过率、未跑项数
