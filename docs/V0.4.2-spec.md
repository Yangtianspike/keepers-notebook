# 守秘人图谱 v0.4.2 需求规格说明

## 版本目标

v0.4.2 聚焦三个模块：**地图融合**（地图为底+人物/线索挂载+多模态识别）、**章节总结**（8 部分结构化摘要+分层展开）、**UX 修复**（确认弹窗即时关闭）。

---

## 一、功能需求

### F1. 地图融合模块

**F1.1 抽象画布**
- 取代 v0.4 的地图占位 UI，启用真实地图画布
- 地点为节点，按坐标摆放在抽象画布上
- KP 可拖拽调整位置，位置存 IndexedDB
- 画布支持缩放、平移

**F1.2 地点坐标三档来源**

| 档位 | 来源 | 实现方式 | 依赖 |
|---|---|---|---|
| ① 文本方位解析 | AI 分析阶段输出地点相对坐标 | place 阶段或 clues 阶段 prompt 增加坐标输出 | 所有模型 |
| ② PDF 图片提取 | pdfjs 提取 PDF 所有图片 → KP 手动选"这是地图" → 在图片上打点定位地点 | 新增图片提取 + 图片选择 UI | 无 |
| ③ 多模态自动识别 | 视觉模型自动识别地图图片+定位地点 | 图片转 base64 发给视觉模型，模型返回地点坐标 | 需视觉模型（Qwen-VL/GLM-4V/GPT-4o） |

- ①默认启用，所有模型都能用
- ②KP 手动选图片时启用，无需模型
- ③用户配了视觉模型时启用，没配则降级为②
- 三档可组合：有地图图片时②/③覆盖①的坐标

**F1.3 多模型视觉支持**
- `ModelConfig` 新增 `visionModel?: string`（视觉模型名称）和 `visionBaseUrl?: string`（视觉模型 API 地址，默认与 chat 相同）
- `ModelMessage.content` 扩展支持 OpenAI vision 格式：`string | null` → `string | null | Array<{type:"text",text:string} | {type:"image_url",image_url:{url:string}}>`
- `route.ts` 新增 `action: "vision"` 处理图片识别请求
- 支持的视觉模型：Qwen-VL（阿里）、GLM-4V（智谱）、GPT-4o（OpenAI）等 OpenAI 兼容格式
- 设置页新增"视觉模型"配置区（可选）

**F1.4 人物/线索挂载**
- **自动关联**：线索通过 `ClueTarget.type === "place"` 关联到地点（已有逻辑）；人物通过线索间接关联（人物是线索 target 且线索关联地点）
- **手动挂载**：KP 可手动把人物/线索拖到地点上，关联关系存 IndexedDB（新增 `PlaceLink` 类型）
- **未关联的不显示**：无法自动关联且未手动挂载的人物/线索，不显示在地图上

**F1.5 就地展开交互**
- 点击地点节点 → 节点放大，周围出现关联人物/线索的小节点
- 再次点击空白处或节点 → 收回展开
- 展开时小节点可点击进入详情（人物 ego 视图/线索详情）

### F2. 章节总结模块

**F2.1 结构化摘要（8 部分）**

每个章节生成 AI 摘要，包含 8 个部分：

| # | 部分 | 详细度 | 说明 |
|---|---|---|---|
| 1 | 故事背景 | 简洁 | 本章故事背景概述 |
| 2 | 时间地点 | 简洁 | 本章发生的时间和地点 |
| 3 | 核心人物 | 简洁 | 本章涉及的核心人物 |
| 4 | 人物经历与动机 | 简洁 | 本章中人物的行为和动机 |
| 5 | 开篇钩子 | 简洁 | 本章开篇吸引玩家的钩子 |
| 6 | 关键线索安排 | **分层展开** | 每条线索分段讲（名称/获取方式/指向） |
| 7 | 场景介绍 | **分层展开** | 每个场景分段讲（地点/发生什么/NPC） |
| 8 | 阶段性重要事件点 | **新增** | Boss 战/重要 NPC 死亡/关键真相揭露，含 CoC 数值（STR/CON/HP/SAN 损失等） |

> 章节总结的生成时机、UI 展示方式待后续讨论确定，v0.4.2 先定义数据结构（F2.1），不实现生成流程和 UI。

### F3. UX 修复

**F3.1 确认弹窗即时关闭**
- KP 点击"接受并继续"或"拒绝并继续"后，**立即关闭弹窗**
- 显示 loading 状态（"继续分析中..."覆盖层或 toast）
- continue 请求完成后，如果有新 ask_user → 再弹窗；如果完成 → 进入下一阶段
- 不再让用户等待 30 秒看着不关闭的弹窗

## 二、非功能需求

| ID | 需求 | 说明 |
|---|---|---|
| N1 | 纯本地优先 | 地点坐标存 IndexedDB；PDF 图片提取纯本地；视觉模型调用走服务端代理 |
| N2 | 隐私不降 | 视觉模型调用只发送图片 base64，不发送用户身份信息；不引入外部地图瓦片 |
| N3 | 降级兼容 | 没有视觉模型时③自动降级为②；没有地图图片时②降级为①抽象画布 |
| N4 | 性能 | 地点 ≤50 个时画布渲染流畅；章节总结生成不阻塞其他操作 |
| N5 | 数据完整 | 旧项目（v0.4 数据）打开无报错，地点数据保留，新增字段默认空 |

## 四、数据模型变更

### 新增类型

```typescript
// 地点坐标
type PlaceCoordinates = {
  x: number;  // 画布坐标 或 图片像素 x
  y: number;
  source: "ai_text" | "manual_drag" | "image_pin" | "vision_model";
};

// 地点-人物/线索关联（手动挂载）
type PlaceLink = {
  id: string;
  placeId: string;
  targetType: "person" | "clue";
  targetId: string;
  source: "auto" | "manual";  // 自动关联还是手动挂载
};

// 章节总结
type ChapterSummary = {
  chapterId: string;
  background: string;              // 1. 故事背景
  timeAndPlace: string;            // 2. 时间地点
  coreCharacters: string;          // 3. 核心人物
  characterArcs: string;           // 4. 人物经历与动机
  openingHook: string;             // 5. 开篇钩子
  clueArrangements: Array<{        // 6. 关键线索安排（分层）
    name: string;
    acquisition: string;
    leadsTo: string;
  }>;
  sceneIntroductions: Array<{      // 7. 场景介绍（分层）
    location: string;
    events: string;
    npcs: string;
  }>;
  keyEvents: Array<{               // 8. 阶段性重要事件点
    title: string;
    type: "boss" | "death" | "revelation" | "checkpoint";
    description: string;
    stats?: {                      // CoC 数值
      str?: number; con?: number; dex?: number; int?: number;
      pow?: number; hp?: number; sanLoss?: string; mp?: number;
    };
  }>;
};
```

### 现有类型扩展

| 实体 | 字段 | 变更 | 说明 |
|---|---|---|---|
| `Place` | `coordinates?` | **新增** | `PlaceCoordinates`，地点在画布/图片上的位置 |
| `Place` | `mapImageId?` | **新增** | 如果用 PDF 图片做底图，关联的图片 ID |
| `ProjectAnalysis` | `placeLinks` | **新增** | `PlaceLink[]`，人物/线索与地点的手动关联 |
| `ProjectAnalysis` | `chapterSummaries` | **新增** | `ChapterSummary[]`，章节总结 |
| `ProjectAnalysis` | `mapImages` | **新增** | `MapImage[]`，从 PDF 提取的图片 |
| `Project` | `mapImageBase?` | **新增** | `string`，KP 选定的地图底图 base64 |
| `ModelConfig` | `visionModel?` | **新增** | 视觉模型名称 |
| `ModelConfig` | `visionBaseUrl?` | **新增** | 视觉模型 API 地址（默认与 chat 相同） |
| `ModelMessage` | `content` | **扩展** | 支持 OpenAI vision 格式数组 |

### 新增类型

```typescript
type MapImage = {
  id: string;
  page: number;        // PDF 页码
  base64: string;      // 图片数据
  width: number;
  height: number;
  selectedAsMap: boolean;  // KP 是否选定为地图底图
};
```

### place 阶段扩展（或复用 clues）

## 六、验收标准（AC1~AC12）

| AC | 验证方式 | 可观测标准 |
|---|---|---|
| **AC1** | 浏览器实测 | 打开地图页签 → 显示抽象画布 → 已确认的地点作为节点显示 → 可拖拽调整位置 → 刷新后位置保持 |
| **AC2** | 浏览器实测 | 点击地点节点 → 就地展开 → 周围出现关联的人物/线索小节点 → 点击小节点可进入详情 → 点击空白收回 |
| **AC3** | 浏览器实测 | 系统自动关联：线索通过 ClueTarget.type="place" 关联到地点 → 该地点展开时显示关联线索 |
| **AC4** | 浏览器实测 | KP 手动挂载：拖拽人物/线索到地点上 → 关联存 IndexedDB → 刷新后保持 |
| **AC5** | 浏览器实测 | ①文本方位解析：分析含方位描述的剧本 → 地点有初始坐标（不堆在中央） |
| **AC6** | 浏览器实测 | ②PDF图片提取：导入含地图图片的 PDF → 图片提取成功 → KP 可选择一张作为底图 → 在图片上打点定位地点 |
| **AC7** | 浏览器实测 | ③多模态识别（需视觉模型）：配置 Qwen-VL → 选定地图图片 → 视觉模型自动识别地点位置 → 坐标自动填入 |
| **AC8** | 浏览器实测 | ③降级：未配视觉模型 → 选图片后降级为手动打点（②逻辑） |
| **AC9** | 代码审查 | `ChapterSummary` 类型定义完整（8 部分，含分层展开的数组和 Boss 数值），数据模型就绪 |
| **AC10** | 浏览器实测 | 实时确认：点"接受并继续"→ 弹窗立即关闭 → 显示 loading → 请求完成后决定下一步 |
