# 守秘人图谱 v0.5 验收交接 Prompt

你是验收 agent，负责验收「守秘人图谱（keeper-atlas）v0.5」。

角色说明：本会话你是验收方，不是规划方。你的职责是按 checklist 逐项验证，报告实际结果。

## 项目速览

- 本地启动：`npm run dev`，浏览器访问 `http://[::1]:3000/`
- 项目数据在浏览器 IndexedDB（库 `keeper-atlas`）
- v0.5 核心改动：7 阶段分析流程、幕模块、章节总结、砍掉 4 个旧模块、UX 修复

## 必读文档（按顺序）

1. `docs/V0.5-checklist.md` — 验收清单（42 项 + 3 个端到端场景）
2. `docs/V0.5-spec.md` — 需求规格（AC1~AC12）
3. `docs/V0.5-plan.md` — 技术设计

## 验收规则

- 逐项执行 checklist 的「验证」方式，先有证据再下结论
- 每项标记：✅ 通过 / ❌ 失败（附问题描述）/ ⏸ 未跑（附原因）
- 浏览器实测项需要 `npm run dev` 启动服务
- 代码审查项用 `read_file` / `search_content` 工具
- 编译测试项用 `execute_command` 工具
- 发现 bug 先记录，不要自己修

## 环境要求

- Node >= 22.13
- 真实 LLM API Key（推荐 DeepSeek）
- 测试剧本 PDF（含人物/线索/分支剧情）
- v0.4 旧项目（用于迁移验证）

## 完成标志

- 42 项 checklist 全部有结论
- 3 个端到端场景全部跑完（或标未跑及原因）
- 输出验收报告：每项结论 + 证据 + 问题描述
- 总结：阻断性缺陷数、通过率、未跑项数
