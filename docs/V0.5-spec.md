# 守秘人图谱 v0.5 需求规格说明

## 版本目标

v0.5 是架构级重构：分析流程从 5 阶段重构为 7 阶段（前 6 全局 + 第 7 分幕），砍掉地图/人物门户/线索图/时间线 4 个模块，新增"幕"模块（含分支树状图），实现章节总结生成和 UI，修复确认弹窗 UX。

---

## 一、功能需求

### F1. 分析流程重构（5 阶段 → 7 阶段）

**F1.1 新 7 阶段定义**

| # | 阶段 | 生成范围 | 内容 | 替代原阶段 |
|---|---|---|---|---|
| 1 | 故事背景 | 全局 | 故事核心、起因、历史、现状、结局 | overview |
| 2 | 时间地点 | 全局 | 时间线和地点信息汇总 | 新（拆分自 overview/clues） |
| 3 | 核心人物 | 全局 | 人物列表（含别名/身份/动机/importance 分级） | people |
| 4 | 人物经历与动机 | 全局 | 人物在故事中的经历和动机详解 | 新 |
| 5 | 开篇钩子 | 全局 | 开篇吸引玩家的钩子 | 新 |
| 6 | 关键线索安排 | 全局 | 线索列表（含获取方式/指向/风险） | clues |
| 7 | 幕 | 按幕生成（多个） | 地点+时间+人物+线索+分支结局 | timeline + relations |

- 前 6 阶段全局生成一次（整个剧本一个结果）
- 第 7 阶段"幕"按幕生成多个（一个剧本包含多个幕）
- 幕的生成基于前 6 阶段的全局结果作为上下文，保证前后一致

**F1.2 确认队列（实时确认）**
- 阻塞阶段：**核心人物（阶段3）**、**关键线索安排（阶段6）**
- 不阻塞阶段：故事背景、时间地点、人物经历与动机、开篇钩子、幕
- 实时确认机制保留 v0.4 的三档模式（Tier 1 function calling / Tier 2 JSON 块 / Tier 3 阶段后阻塞）
- 幕阶段不阻塞（直接生成，生成后 KP 可手动编辑）

### F2. 幕模块

**F2.1 幕的数据结构**

每个幕包含：
- **幕标识**：id、标题、序号（第一幕/第二幕/...）
- **地点**：该幕发生的地点（引用 Place 或自由文本）
- **时间**：该幕发生的时间（相对时间或绝对时间）
- **人物**：该幕涉及的人物列表（引用 Person，含在该幕中的角色）
- **线索**：该幕涉及的线索列表（引用 Clue，含在该幕中的作用）
- **分支结局**：该幕结尾的分支条件
  - 分支条件（如"XX 死了"→进入幕A，"XX 活着"→进入幕B）
  - 每个分支指向下一幕的 id
- **阶段性重要事件点**：Boss 战/重要 NPC 死亡/关键真相揭露，含 CoC 数值（STR/CON/HP/SAN 损失等）
- **幕描述**：文字描述该幕发生什么

**F2.2 幕的可视化展示**
- 幕列表：垂直排列，每幕一张卡片，显示标题/地点/时间/人物/线索/分支
- 展开交互：点击幕卡片 → 展开详情，显示人物卡（分层）和线索卡（分层）
- 人物卡关联查看：点击幕里的人物卡 → 查看该人物在其他幕的出现记录

**F2.3 分支树状图**
- 全局视图：所有幕按分支关系组成树状图
- 节点：幕（显示幕标题）
- 边：分支条件（如"XX 死了"→下一幕）
- 用 React Flow 渲染（已有依赖）
- 支持缩放、平移、点击节点跳转到幕详情

**F2.4 幕的编辑**
- KP 可手动编辑幕（修改标题/地点/时间/描述）
- KP 可手动添加/删除分支
- KP 可手动调整分支指向
- 编辑后存 IndexedDB

### F3. 章节总结

**F3.1 数据结构（8 部分）**

每个章节生成 AI 摘要，包含 8 个部分：

| # | 部分 | 详细度 | 说明 |
|---|---|---|---|
| 1 | 故事背景 | 简洁 | 本章故事背景概述 |
| 2 | 时间地点 | 简洁 | 本章发生的时间和地点 |
| 3 | 核心人物 | 简洁 | 本章涉及的核心人物 |
| 4 | 人物经历与动机 | 简洁 | 本章中人物的行为和动机 |
| 5 | 开篇钩子 | 简洁 | 本章开篇吸引玩家的钩子 |
| 6 | 关键线索安排 | **分层展开** | 每条线索分段讲（名称/获取方式/指向） |
| 7 | 幕 | **分层展开** | 每个幕分段讲（地点/时间/人物/线索/分支） |
| 8 | 阶段性重要事件点 | **含 Boss 数值** | Boss 战/重要 NPC 死亡/关键真相揭露，含 CoC 数值（STR/CON/HP/SAN 损失等） |

**F3.2 生成时机**
- 章节总结在分析流程完成后生成（7 阶段全跑完后）
- 或作为分析流程的最后一步（阶段 7 幕生成后，自动生成章节总结）
- 生成后存入 `ProjectAnalysis.chapterSummaries`

**F3.3 UI 展示**
- 文档结构页（StructureView）每章节下方显示"查看总结"按钮
- 点击展开章节总结面板，按 8 部分结构化展示
- 关键线索安排和幕部分支持折叠/展开各子项

### F4. UX 修复

**F4.1 确认弹窗即时关闭**
- KP 点击"接受并继续"或"拒绝并继续"后，**立即关闭弹窗**
- 显示 loading 状态（"继续分析中..."覆盖层）
- continue 请求完成后，如果有新 ask_user → 再弹窗；如果完成 → 进入下一阶段
- 不再让用户等待 30 秒看着不关闭的弹窗

## 四、数据模型变更

### 新增类型

```typescript
// 幕
type Act = {
  id: string;
  title: string;
  sequence: number;           // 序号（1=第一幕）
  placeId?: string;           // 关联地点（引用 Place）
  placeText?: string;         // 地点自由文本（如果没关联 Place）
  time: string;               // 时间（相对或绝对）
  personIds: string[];        // 涉及人物（引用 Person）
  clueIds: string[];          // 涉及线索（引用 Clue）
  branches: ActBranch[];      // 分支结局
  keyEvents: KeyEvent[];      // 阶段性重要事件点
  description: string;        // 幕描述
};

// 分支
type ActBranch = {
  id: string;
  condition: string;          // 分支条件（如"XX 死了"）
  nextActId?: string;         // 指向下一幕（如果还有）
  isEnding?: boolean;         // 是否是结局
  endingType?: "good" | "bad" | "neutral";  // 结局类型
};

// 阶段性重要事件点
type KeyEvent = {
  title: string;
  type: "boss" | "death" | "revelation" | "checkpoint";
  description: string;
  stats?: CoCStats;           // CoC 数值
};

// CoC 数值
type CoCStats = {
  str?: number; con?: number; dex?: number; int?: number;
  pow?: number; hp?: number; sanLoss?: string; mp?: number;
};

// 章节总结
type ChapterSummary = {
  chapterId: string;
  background: string;
  timeAndPlace: string;
  coreCharacters: string;
  characterArcs: string;
  openingHook: string;
  clueArrangements: Array<{ name: string; acquisition: string; leadsTo: string }>;
  acts: Array<{ actId: string; title: string; summary: string }>;
  keyEvents: KeyEvent[];
};
```

### 现有类型扩展

| 实体 | 字段 | 变更 | 说明 |
|---|---|---|---|
| `AnalysisStage` | — | **改枚举** | 从 5 阶段改为 7 阶段 |
| `ProjectAnalysis` | `acts` | **新增** | `Act[]`，幕列表 |
| `ProjectAnalysis` | `chapterSummaries` | **新增** | `ChapterSummary[]`，章节总结 |
| `ProjectAnalysis` | `relations` | **删除** | 人物关系并入幕 |
| `ProjectAnalysis` | `timeline` | **删除** | 被幕取代 |
| `ProjectAnalysis` | `places` | **保留** | 地点数据仍需要（幕引用） |

### `AnalysisStage` 枚举变更

```typescript
// v0.4（旧）
type AnalysisStage = "overview" | "people" | "relations" | "timeline" | "clues";

// v0.5（新）
type AnalysisStage =
  | "background"      // 1. 故事背景
  | "timeplace"       // 2. 时间地点
  | "characters"      // 3. 核心人物
  | "characterArcs"   // 4. 人物经历与动机
  | "openingHook"     // 5. 开篇钩子
  | "clues"           // 6. 关键线索安排
  | "acts";           // 7. 幕
```

### 数据迁移

- v0.4 旧项目打开时：
  - `relations` 数据迁移到幕（尝试按人物对分配到相关幕，无法分配的丢弃）
  - `timeline` 数据迁移到幕（每个 timeline event 尝试转为幕的 keyEvent）
  - `places` 数据保留
  - `people` 数据保留
  - `clues` 数据保留
  - 新增 `acts: []`、`chapterSummaries: []` 默认空

## 五、分析流水线架构

### 流程图

```
用户点击"开始分析"
  → 阶段1：故事背景（全局，不阻塞）
  → 阶段2：时间地点（全局，不阻塞）
  → 阶段3：核心人物（全局，阻塞——实时确认）
  → 阶段4：人物经历与动机（全局，不阻塞）
  → 阶段5：开篇钩子（全局，不阻塞）
  → 阶段6：关键线索安排（全局，阻塞——实时确认）
  → 阶段7：幕（按幕生成，不阻塞，基于前6阶段结果）
  → 章节总结生成（基于7阶段结果）
  → 分析完成
```

### 幕阶段生成逻辑

```
阶段7：幕
  输入：前6阶段的全局结果（人物列表/线索列表/地点列表/故事背景）
  模型任务：根据剧情节点划分幕，每幕包含地点/时间/人物/线索/分支
  输出：Act[]（多个幕，含分支关系）
  
  模型可能需要多次调用：
  - 第一次调用：生成幕的骨架（幕列表+分支关系）
  - 后续调用：为每个幕填充详细信息（人物/线索/事件点）
```
