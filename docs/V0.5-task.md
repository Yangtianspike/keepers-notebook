## T1: 数据类型定义更新

**文件**：`lib/types.ts`
**依赖**：无

**步骤**：
1. `AnalysisStage` 枚举从 5 阶段改为 7 阶段：
   ```typescript
   export type AnalysisStage =
     | "background" | "timeplace" | "characters" | "characterArcs"
     | "openingHook" | "clues" | "acts";
   ```
2. 新增类型：`Act`、`ActBranch`、`KeyEvent`、`CoCStats`、`ChapterSummary`、`TimePlace`、`CharacterArc`
3. `ProjectAnalysis`：
   - 新增 `acts: Act[]`、`chapterSummaries: ChapterSummary[]`、`timePlace?: TimePlace`、`characterArcs?: CharacterArc[]`、`openingHook?: string`
   - 删除 `relations`、`timeline`、`relationshipLayout`、`clueLayout`
4. `emptyAnalysis` 更新：新字段默认值，删除旧字段
5. 保留 `Person`、`Clue`、`Place`、`ReviewItem` 不变

**验证**：
- `npx tsc --noEmit` 零类型错误（可能有引用旧阶段的错误，记录下来在 T3 中修）

## T2: 数据迁移（DB v3→v4）

**文件**：`lib/storage.ts`
**依赖**：T1

**步骤**：
1. `DB_VERSION` 从 3 改为 4
2. `onupgradeneeded` 中增加 v3→v4 迁移：

**验证**：
- 用 v0.4 旧项目打开 → 无报错 → `acts` 有数据（迁移的）→ 无 `relations`/`timeline` 字段
- 新建项目 → `acts: []`、`chapterSummaries: []`

## T3: 分析流程 prompt 重写

**文件**：`app/api/model/route.ts`
**依赖**：T1

**步骤**：
1. `stageInstructions` 函数重写 7 个阶段的 prompt：
   - `background`：故事背景（替代 overview）
   - `timeplace`：时间地点汇总
   - `characters`：核心人物（替代 people，保留 importance 分级）
   - `characterArcs`：人物经历与动机（基于已确认人物列表）
   - `openingHook`：开篇钩子
   - `clues`：关键线索安排（同 v0.4 clues）
   - `acts`：幕（两次调用：骨架+填充）
2. `maxTokensFor` 更新阶段映射
3. acts 阶段的特殊处理：
   - 第一次调用：生成幕骨架（列表+分支关系）
   - 第二次调用：为每幕填充详情（描述+keyEvents）
   - 或单次调用生成完整幕（如果模型能力强）

**验证**：
- 代码审查：7 个阶段 prompt 都存在
- `npx tsc --noEmit` 零类型错误

## 执行规则

- **连续执行**：中间不要汇报进度、不要停下来等确认；只有全部完成、或真正被阻塞时才停下来输出
- 按 T1→T14 编号顺序串行执行
- 每个任务完成后运行其「验证」步骤，有证据再标记完成
- 每项一个独立 commit，不与无关改动混合
- 只修任务清单列出的任务；发现其他问题记录报告，不顺手改
- 写/改文件保持正常缩进换行，禁止输出压缩成单行的代码
- T5 删除旧模块时逐段删，每段 build 验证；误删共享代码立即回滚
