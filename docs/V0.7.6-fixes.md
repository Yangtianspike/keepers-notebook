# V0.7.6 补丁：统一书页文档、可视化编辑与实体资料卡

## 背景

V0.7.5 完成了书页分页保护、基础文字编辑和分析流程展示优化。后续实际使用中继续暴露出以下问题：

1. 前六阶段与“幕”虽然已经进入同一本书，但内容生成、编辑方式和分页边界仍不完全统一。
2. 原有逐字段编辑只能修改预先划定的文字，无法像文档一样自由修改标题、增加段落和添加笔记。
3. 直接编辑 Markdown 要求用户理解 Markdown 语法，不适合作为默认编辑体验。
4. turn.js 外层章节标题与 Markdown 一级标题重复显示。
5. 整段内容作为一个 DOM 块参与分页时，仍可能在书页底部截断文字。
6. 上一页、下一页、页码、编辑与幕树入口分散，缺少直接跳页能力。
7. 分析流程的“分析剧本”“重新分析”“分析记录”入口不统一，并存在重复入口。
8. 人物、地点、线索和事件只作为静态文字出现，无法从正文直接查看资料或跳转。
9. AI 生成资料与 KP 自建资料缺少统一、可持续编辑的数据结构。

V0.7.6 将这些连续改动整理为一个累积补丁。本文记录的是最终实现状态，不保留已经被后续方案替代的中间 UI。

## 1. 前六阶段与所有幕统一为一本书

### 问题

此前前六阶段和幕详情存在不同渲染分支，容易导致：

- 幕只接入第一幕或部分幕。
- 阶段页码与幕页码分别计算。
- 左侧阶段导航跳转后重新初始化另一套书页。
- 幕详情保留独立按钮、独立编辑和不同视觉结构。

### 最终实现

- 前六阶段和所有幕统一生成 `markdownSections`。
- 所有 section 按固定顺序进入同一个 `renderedBookSections` 数组。
- `StageView` 只维护一套 `pages`、总页码和当前页码。
- 全部内容共用同一个 turn.js 实例。
- 左侧“剧本解析”阶段按钮通过 `activeSectionKey` 定位对应 section 的第一页。
- 幕页与前六阶段使用同一分页、编辑、实体识别和书页样式。
- 幕默认文档包含：
  - 人物；
  - 线索；
  - 关键事件；
  - 分支结构；
  - 幕描述。

### 结果

- 页码按整本书连续统计。
- 从任一阶段翻到幕、从幕翻回阶段时不会切换书实例。
- 所有幕都会进入统一书页数组，不再只处理第一幕。

## 2. turn.js 生命周期稳定性延续

V0.7.5 之前已经针对 turn.js 做过实例隔离和销毁修复。V0.7.6 的统一文档实现继续遵循这些约束：

- React 只负责提供稳定的原始书页节点。
- turn.js 管理的包装节点不参与 React 重用。
- 离开书页视图时停止翻页动画、解绑事件并销毁旧实例。
- 返回书页视图时根据新的 pages 重建实例。
- 翻页过程中新的跳页请求进入等待队列，不同时操作 DOM。
- 内容修改后使用显式 `contentKey` 触发重测和重建，避免由新建 ReactNode 引发更新循环。

这些约束用于避免：

- `HierarchyRequestError: insertBefore`；
- `Maximum update depth exceeded`；
- 离开书页再返回后跳转章节时的概率性崩溃；
- turn.js 旧折页动画继续操作已经卸载的父节点。

## 3. 书页内容统一为 Markdown 底层文档

### 设计

每个阶段或幕都有一份 Markdown 文档：

```ts
type KPNotes = {
  sectionMarkdown?: Record<string, string>;
};
```

key 使用现有 section 标识：

- `stage-background`
- `stage-timeplace`
- `stage-characters`
- `stage-characterArcs`
- `stage-openingHook`
- `stage-clues`
- `acts:<actId>`

### 行为

- 没有用户文档时，根据当前分析结果生成默认 Markdown。
- 用户保存编辑后，把该 section 的完整 Markdown 写入 `kpNotes.sectionMarkdown`。
- 阅读模式与编辑模式读取同一份 Markdown，不再维护两套内容结构。
- 旧版 `stageViewOverrides`、`actViewOverrides` 和 `sectionNotes` 类型继续保留，避免破坏已有本地项目；新编辑流程以 `sectionMarkdown` 为准。

### 编辑方案演进

本补丁期间编辑方式经过三步演进：

1. 逐字段虚线编辑；
2. 原始 Markdown 文本编辑；
3. 最终的可视化文档编辑。

前两种是过渡实现。V0.7.6 默认提供第 3 种方式，Markdown 源码仅作为辅助模式保留。

## 4. 可视化书页编辑器

### 默认体验

点击“编辑书页”后进入独立编辑工作区。用户不需要了解 Markdown，可以像编辑普通文档一样修改：

- 一级、二级、三级标题；
- 普通段落；
- 粗体；
- 无序列表；
- 有序列表；
- 引用；
- 分隔线；
- 新增段落；
- 撤销与重做。

### 自由编辑

- 可修改原有标题，不再局限于虚线框内的字段。
- 可自由增加段落、标题、列表和 KP 笔记。
- 编辑器按 section 切换，但保存时一次写回整本书的草稿集合。
- 仅在点击“保存并返回书页”时持久化，不在每次按键时写 IndexedDB。

### Markdown 源码模式

- 工具栏保留“Markdown 源码”入口。
- 可视化 HTML 与 Markdown 之间提供双向转换。
- Markdown 仍是持久化格式，不把浏览器生成的 HTML 直接存入项目。

### 性能处理

- 输入过程主要更新编辑 DOM 和内存草稿。
- 不在每个字符输入时重建 turn.js。
- 保存完成并返回阅读模式后，才重新分页和初始化书实例。

## 5. 修复标题重复

### 原因

标题曾同时来自两处：

1. `StageView` 外层固定渲染的 `section.name`；
2. Markdown 文档中的 `# 一级标题`。

### 修改

- 移除书页外层固定章节名称。
- `StageView` 外层仅保留阶段序号，例如 `02 / 12`。
- 书页中唯一可见的章节标题来自 Markdown。
- Markdown 标题可在可视化编辑器中直接修改。
- 左侧导航名称保持系统固定名称，不随正文标题一起改变。

## 6. 块级分页与文字截断修复

### 原因

把完整 Markdown 文档作为单一 React 节点交给旧分页器后，超高节点仍会采用 `translateY` 像素切片，可能从一行文字中间截断。

### 最终分页单位

Markdown 在进入 `StageView` 前被解析为独立块：

- 标题；
- 段落；
- 单个列表项；
- 引用；
- 分隔线。

每个块独立测量并参与分页。

### 分页规则

- 当前页空间不足时，完整块移动到下一页。
- 标题带有 `data-keep-with-next` 标记，尽量与后续第一块一起移动。
- 列表逐项生成分页块，避免整个长列表被当作一个超高节点。
- 普通长段落在进入分页器前优先按中文标点或单词边界拆成安全片段。
- 卡片和资料块不再按像素从中间裁开。
- 只有无法进一步拆分的异常超高节点才保留旧切片兜底。

### 结果

- 不再从普通文字行中间切页。
- 标题不会常规性地孤立在页尾。
- 阶段和幕使用完全相同的分页算法。

## 7. 书页顶部统一工具条

原底部翻页栏和分散按钮被整合为顶部工具条，包含：

```text
[← 上一页] [当前页 / 总页数] [跳至 __ 页] [跳页] [编辑书页] [幕树] [下一页 →]
```

### 具体行为

- “上一页”“下一页”调用当前 turn.js 实例。
- 翻页动画进行中按钮暂时禁用，避免重复命令。
- 输入页码并按 Enter 或点击“跳页”即可定位。
- 跳页范围自动限制在 `1...总页数`。
- “幕树”仅在当前书页属于 `acts:*` 时显示。
- 键盘左右方向键继续可用。
- 输入框、文本框、选择框和 `contenteditable` 获得焦点时，不拦截方向键。
- 原底部页码和翻页按钮删除。

## 9. 分析流程统一为整体分析

### 分析入口

分析流程顶部统一为三个按钮：

- **分析剧本**：从第一个未完成阶段开始，连续执行后续阶段。
- **重新分析**：确认后重置七个阶段状态，从故事背景开始重新分析。
- **分析记录**：打开独立可关闭窗口查看活动日志。

### UI 调整

- 三个按钮保持同一水平线、相同高度和圆角。
- “分析剧本”为实心青绿色主按钮。
- “重新分析”和“分析记录”为青绿色描边按钮。
- 禁用状态统一使用暗色面板与弱化文字，保持可读。
- 删除每个完成阶段后的“重新分析”按钮。
- 删除阶段内冗余“查看结果”入口，阶段卡本身可点击进入阅读。
- 删除页面右上角重复的“分析剧本”和“备本已生成”。
- “前往配置”与右上角设置图标统一打开同一个设置模态框。

### 分析记录

- 分析记录不再常驻占用分析页面空间。
- 点击按钮后打开 `AnalysisLogModal`。
- 窗口可独立关闭，并显示各阶段执行、暂停、确认、完成和错误记录。

### 服务端边界

- 本补丁不改变模型服务端的七阶段分析协议。
- “整体分析”由客户端串行控制既有阶段调用完成。

## 10. 项目仪表盘“继续工作”区域

旧“核心视图”仅重复提供故事背景和幕两个入口，信息价值较低。本补丁将其替换为项目状态与下一步工作：

- 根据项目状态显示：
  - 处理待确认项；
  - 继续分析；
  - 继续阅读。
- 显示最近阅读的 section 和页码。
- 显示分析完成数量、待确认数量和错误数量。
- 显示项目最后更新时间。
- 显示最近五条分析活动。

阅读位置通过以下结构保存：

```ts
type ReadingPosition = {
  sectionKey: string;
  page: number;
  updatedAt: string;
};
```

## 11. 统一实体资料系统

### 支持的实体类型

V0.7.6 支持：

- 人物 `person`
- 线索 `clue`
- 地点 `place`
- 事件 `event`
- 自定义 `custom`

明确不新增“组织”模板。

### 统一模型

AI 生成实体和 KP 创建实体使用同一个 `EntityCard`：

```ts
type EntityCard = {
  ref: string;
  id: string;
  kind: "person" | "clue" | "place" | "event" | "custom";
  source: "source" | "inference" | "keeper";
  confirmed: boolean;
  original: {
    name: string;
    aliases: string[];
    tags: string[];
    playerVisible: string;
    keeperPrivate: string;
    fields: Record<string, string | string[] | boolean>;
  };
  overrides?: EntityOverrides;
  appearances: Array<{ sectionKey: string; label?: string }>;
  linkBehavior: { jump: boolean; preview: boolean };
  createdAt: string;
  updatedAt: string;
};
```

### AI 原始层与 KP 覆盖层

- `original` 来自当前 AI 分析结果或原始剧本。
- `overrides` 只保存用户修改。
- 显示时使用 `original + overrides` 合并结果。
- 重新分析可以更新 AI 原始层，但不会直接清除 KP 覆盖层。

### 删除规则

- AI/剧本来源实体始终可以编辑，但不能删除。
- KP 创建实体可以编辑和删除。
- 删除 KP 实体时只删除实体卡和关联关系，不删除书页中已经存在的普通可见文字。

### 模板字段

不同实体类型提供各自字段集合：

- 人物：身份、重要程度、外貌、性格、动机、秘密、状态、扮演提示等。
- 线索：内容、来源、位置、获取方式、指向、关键性、替代获取和卡关补救等。
- 地点：区域、描述、第一印象、内部区域、进入条件、危险、人物与线索等。
- 事件：时间、地点、人物、起因、经过、结果、触发条件和后果等。
- 自定义：类别、摘要、正文、状态和自定义字段。

空字段在阅读状态不显示，进入编辑状态后仍可填写。

## 12. 羊皮纸实体资料窗口

### 显示方式

- 实体资料使用与书页一致的羊皮纸背景。
- 窗口覆盖在当前界面上，可随时关闭。
- 标题显示实体类型及来源标记。
- 所有实体窗口始终提供“编辑资料”。

### 窗口导航

实体窗口使用单一历史栈，不叠加多层模态框：

- `← 返回`：返回上一个实体。
- `×`：关闭整个实体窗口。
- 点击关联实体：在同一窗口中进入该实体。

### 关联层级

数据结构和 UI 支持：

- 直接关联；
- 间接关联；
- 模型推断；
- KP 关联。

当前可自动建立幕内人物与线索的直接关联，也可由 KP 新建关联实体并生成 KP 关联。

## 13. 书页中的实体链接

### 自动识别

- 阅读模式根据实体名称和别名识别正文中的人物、地点、线索和事件。
- 仅自动链接唯一匹配的名称，避免同名实体误链接。
- 名称按长度排序，优先匹配较长名称。
- 人物名称使用斜体显示，并带有实体类型对应的颜色与下划线提示。

### 点击行为

点击实体名称后打开小型羊皮纸操作菜单，可提供：

1. 跳转到实体主要所属 section；
2. 打开实体资料窗口。

默认 AI 实体同时启用两种行为。KP 可在实体编辑窗口中改为：

- 仅跳转；
- 仅打开窗口；
- 两者都提供。

### 显式链接格式

编辑器使用内部链接协议保存实体关联：

```text
keeper://person/<id>?jump=1&preview=1
```

实际存入 Markdown 时使用标准链接语法包裹：

```md
[林墨](keeper://person/person-id?jump=1&preview=1)
```

## 14. 在可视化编辑器中创建和关联实体

### 关联已有实体

1. 在可视化编辑器中选中文字。
2. 点击“关联实体”。
3. 选择已有实体。
4. 选择“跳转”和/或“资料窗口”。
5. 写入内部 Markdown 链接。

### 创建新实体

- 选中文字后可以选择人物、线索、地点、事件或自定义类型。
- 系统使用选中文字作为初始实体名称。
- 新实体来源标记为 `keeper`。
- 新实体默认同时启用跳转和资料窗口。
- 实体创建后立即可以与选中文字关联。

### 在资料窗口中创建关联实体

- 点击“新建关联实体”。
- 选择实体类型并输入名称。
- 创建后生成一条 KP 关联，并在同一个窗口历史中打开新实体。

## 数据结构变更

`KPNotes` 新增：

```ts
type KPNotes = {
  stageViewOverrides?: Record<string, Record<string, string>>;
  actViewOverrides?: Record<string, Record<string, string>>;
  sectionNotes?: Record<string, KPNoteBlock[]>;
  sectionMarkdown?: Record<string, string>;
  entityOverrides?: Record<string, EntityOverrides>;
  keeperEntities?: EntityCard[];
  entityRelations?: EntityRelation[];
};
```

兼容策略：

- 所有新增字段均为可选字段。
- 旧项目没有这些字段时使用空对象或空数组。
- 不需要提升 IndexedDB schema 版本。
- 不删除旧覆盖字段，已有项目仍可正常载入。

## 已知边界

1. 实体“跳转”当前定位到实体的主要 section，不保证定位到该实体在 section 内的精确文字行。
2. 自动实体链接只处理唯一名称或别名；同名实体需要在编辑器中手动关联。
3. 当前自动关系主要覆盖同一幕中的人物—线索直接关系；间接与推断关系的数据结构和 UI 已具备，但需要后续分析协议提供更多关系数据。
4. Markdown 转换器支持当前工具栏提供的格式，不以完整 CommonMark/GFM 兼容为目标。
5. 极端超长且无法按文本拆分的自定义节点仍使用旧分页兜底逻辑。
6. 原始 PDF 阅读依赖浏览器对 PDF iframe 的支持；不支持时仍可从项目保存的提取文本查看内容。
