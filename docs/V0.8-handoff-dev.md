# 守秘人图谱 v0.8 Handoff → 开发 Agent

## 角色与目标

你是开发 agent，负责按 v0.8 文档实现代码。规划文档中的说明是执行依据，不是让本会话继续规划。

项目当前实际技术栈为 Next.js 16.2.6、React 19.2.6、TypeScript、Tailwind CSS、vinext/Vite、turn.js 1.0.5 和 jQuery 3.7.1。开发前以 `package.json` 与现有代码为准，不按旧版依赖假设实现。

## 必读文件

1. `docs/V0.8-spec.md`：需求规格与验收边界。
2. `docs/V0.8-plan.md`：技术设计与兼容策略。
3. `docs/V0.8-task.md`：T1→T11 开发任务，唯一执行顺序。
4. `docs/V0.8-checklist.md`：P0 验收清单。
5. `docs/V0.7.6-fixes.md`：当前统一书页、编辑器和实体系统背景。

## 已确认的产品决定

### 模型与协议

- 保持现有七阶段、API action、暂停/确认和整体分析控制流。
- 允许向 characters、characterArcs、acts 响应增加可选字段，旧响应必须继续可用。
- characters 可补充摘要、外貌、性格、状态、扮演提示，以及完整的 CoC 7e 属性。
- 核心人物与非核心人物都可有 CoC 属性。
- 原文未提供数值时，模型允许合理推断，但每个属性、技能和攻击必须独立标记来源/推断并可保留来源引用；KP override 优先。
- 保留旧 `openingHook: string`，新增可选五字段详情，由模型自动生成主持导入内容且不复述序幕。
- characterArcs 可补充动机变化和与主线关系。
- acts 应根据幕内容为所有 `personIds` 总结人物行动，保留 `SourceRef[]` 和 `source | inference | none` 标记。没有明确行动时如实标注，不编造。

### 书页内容

- 核心人物卡的 Markdown 指令只保存实体引用，显示内容从当前实体动态读取。
- 普通幕标题使用 `act.sequence`。只有原始标题明确写“序幕”才保留序幕，不能把数组第一项自动当序幕。
- 开篇钩子固定包含 GM 开场朗读、玩家初始处境、首个冲突、氛围建议、导入技巧。
- “幕描述”改为“本幕剧情”，人物行动位于正文前部。

### 编辑与安全

- 先建立阅读器和编辑器共用的 Markdown AST/解析/序列化层，再扩展编辑工具栏。
- P0 必须包含 H1–H6、斜体、下划线、删除线、表格、图片和字体切换，表格/图片不可延后。
- 内嵌 HTML、属性、字体和 URL 使用白名单，禁止脚本、事件属性和危险协议。
- 本地图片用原生 canvas 压缩，最长边不超过 1600px，目标单图约 1MB。
- 项目只保存 Data URL，不保存刷新即失效的 blob URL。
- 已有 `sectionMarkdown` 不自动覆盖；用户必须通过显式入口并二次确认后应用 v0.8 模板。

### 实体窗口

- 实体类型保持 person、clue、place、event、custom，本版本不增加 organization 模板。
- AI 实体不可删除但始终可编辑；KP 创建实体按既有规则编辑和删除。
- 羊皮纸实体窗口采用 viewport fixed 定位，可拖动、置顶、关闭。
- 同一实体只保留一个窗口，重复打开时聚焦；离开阅读页、切换项目或进入编辑模式时全部关闭。
- 相关实体与人物出场信息从当前项目动态计算，不把关系快照复制进 Markdown。

## 不可破坏的边界

1. 不替换 turn.js，不拆分统一书页：前六阶段和所有幕继续共用同一个 `pages` 数组和 turn.js 实例。
2. 不引入第三方富文本编辑器。
3. 不改变左侧菜单整体风格和桌面背景。
4. 不升级 IndexedDB schema；新增数据字段保持可选并向后兼容。
5. 不实现 PDF 导出。
6. 不顺手修复任务单外的问题；只记录到交付报告。

## 执行规则

- 按 `docs/V0.8-task.md` 的 T1→T11 串行开发，每项完成验证后再进入下一项。
- 每项一个独立 commit，不混入无关改动或历史未跟踪文件。
- 写改文件保持正常缩进和换行。
- 每项验证应留下命令结果或人工复现证据。
- 最终运行 `npm run lint`、`npm run build`、`npm run test`。

## 交付要求

完成后生成 `docs/V0.8-handoff-accept.md`，至少包含：

1. T1→T11 每项的改动文件与内容摘要。
2. 对应验证命令、人工场景与结果。
3. `docs/V0.8-checklist.md` 每个 P0 项的通过/不通过证据。
4. 任务外发现但未修改的问题。
5. 每项 commit hash 和最终 HEAD。
