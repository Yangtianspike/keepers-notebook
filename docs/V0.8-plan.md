# V0.8 Plan：技术设计方案

## 设计原则

1. **复用现有组件**：V0.7.6 已经建立了 `book-editor.tsx`、`markdown-document.tsx`、`entity-window.tsx` 和统一书页架构，V0.8 以扩展为主，不推倒重来。
2. **样式统一入口**：所有按钮风格通过单一 CSS 类控制，避免分散维护。
3. **Markdown 作为事实来源**：内容扩展（核心人物、本幕剧情、开篇钩子）仍通过默认 Markdown 模板生成；编辑器增强产生的 HTML 片段最终也以 Markdown 形式持久化。
4. **实体窗口与书页解耦**：资料窗口不再依赖文字流位置，使用浮动定位 + 拖拽，和书页渲染独立。
5. **渐进增强**：表格、图片、字体切换等编辑器功能先保证基础可用，复杂交互（如表格行列增删、图片拖拽缩放）后续再扩展。
6. **协议向后兼容扩展**：API action、七阶段顺序与确认流程不变；人物、人物弧线和幕只增加可选字段。
7. **实体单一事实来源**：人物卡 Markdown 只保存实体引用，不复制人物属性值。

---

## 0. 共享 Markdown 基础层

当前 `markdown-document.tsx` 的行级解析器只支持 H1–H4、粗体、列表、引用、分隔线和 keeper 链接。人物指令、H5/H6、斜体、删除线、HTML 标记、表格和图片必须先进入同一套块 AST 与行内 token 流，再由阅读器和编辑器共用。

建议新建 `lib/markdown.ts`：

- `parseMarkdown(markdown): MarkdownBlock[]`
- `renderEditableHtml(blocks): string`
- `serializeEditableHtml(root): string`
- `sanitizeInlineHtml(value): SafeInlineNode[]`
- 支持 heading 1–6、paragraph、list item、quote、divider、table、image、character directive。
- 支持 bold、italic、strike、underline、font token、keeper link。
- 字体保存为受控 `data-font="serif|sans|kai"`，渲染时映射到固定 CSS 字体栈，不接受任意 style。
- HTML 仅保留白名单标签与属性；URL 仅允许 http、https 和受控 data:image。

`markdown-document.tsx` 只负责把 AST 转成可分页 React block；`book-editor.tsx` 只负责编辑 DOM 与调用序列化器。

## 2. 核心人物 section 重构

### 2.1 方案

核心人物阶段（`stage-characters`）的默认 Markdown 由当前项目人物实体动态生成。人物卡使用只包含实体引用的原子指令，阅读时从最新实体 `original + overrides` 动态取值。

### 2.2 涉及文件

| 文件 | 改动 |
|---|---|
| `lib/entities.ts` 或 `app/page.tsx` | 生成 `stage-characters` 默认 Markdown |
| `app/components/markdown-document.tsx` | 新增核心人物渲染逻辑（按 importance 分组） |
| `app/globals.css` | 核心人物卡片、表格样式 |

### 2.3 Markdown 结构

```md
# 核心人物

## 核心人物

:::character-card{"ref":"person:person-1","importance":"core"}
:::

## 重要人物

:::character-card{"id":"person-2","importance":"important"}

### 苏婉
...

:::

## 次要人物

- **陈警官**：警察，提供官方文件。
- **老张**：目击者。
```

### 2.4 渲染逻辑

- `markdown-document.tsx` 识别 `:::character-card` 自定义容器。
- 根据 `importance` 决定渲染为大卡片、中卡片或列表项。
- 表格字段由实体 `original.fields`、`cocStats` 与 `overrides` 合并生成。
- 卡片标题直接调用实体窗口，不在 Markdown 中保存一份姓名副本。
- 可视化编辑器把人物卡视为原子块；编辑字段时打开实体资料窗口。
- 核心人物渲染完整资料与 CoC 表；重要人物渲染主要属性、关键技能和攻击；次要人物紧凑显示。

### 2.5 人物模型输出扩展

修改 `app/api/model/route.ts` 的 characters 提示词和客户端解析，给 `Person` 增加可选的 `summary`、`appearance`、`personality`、`state`、`performanceHints` 和 `cocStats`。

- 原文存在数值：直接提取，在对应 `fieldProvenance` 项标记 `source` 并保留 `SourceRef[]`。
- 原文缺失：允许按 CoC 7版、人物年龄/身份/作用生成，在对应字段标记 `inference`。
- 技能和攻击各自保存 provenance，禁止用整张卡单一标签掩盖来源值与推断值混合的情况。
- 推断技能和攻击必须保持数值范围合法。
- 旧人物没有新字段时正常加载。

## 5. 幕章节命名去重

### 5.1 方案

生成 `acts:<actId>` 的默认 Markdown 标题时，先检查模组原始标题是否已包含序幕/幕字样。

### 5.2 判断规则

```ts
function buildActTitle(originalTitle: string, sequence: number): string {
  const hasActPrefix = /^(第[一二三四五六七八九十\d]+幕|序幕|终幕)/.test(originalTitle.trim());
  const title = originalTitle.trim();
  if (hasActPrefix) return title;
  return title ? `第 ${sequence} 幕 · ${title}` : `第 ${sequence} 幕`;
}
```

实际调用传入 `act.sequence`，不要用数组第一项推断序幕。只有原始标题明确写有“序幕”时才保留序幕。

### 5.3 涉及文件

| 文件 | 改动 |
|---|---|
| `app/page.tsx` 或 Markdown 模板 | 幕标题生成逻辑 |

## 6. 幕描述 → 本幕剧情 + 人物行动摘要

### 6.1 方案

`acts:<actId>` 默认 Markdown 在原有内容前增加人物行动摘要。模型在现有 acts 阶段为每个 `personId` 输出可选 `personActions`，不新增分析阶段。

### 6.2 人物动作来源

- 优先读取 `act.personActions`，每条包括 `personId`、`summary`、`provenance` 和 `sources`；provenance 支持 `source | inference | none`。
- 提示词要求覆盖全部 `personIds`，基于该幕原文总结行为并保留来源。
- 原文无明确动作时标记 `none`，并明确写“本幕无明确行动”，不得把单纯出场补写成行为。
- 旧项目没有 `personActions` 时，从 `act.description` 提取包含人物名的句子；仍找不到才使用出场兜底。

### 6.3 Markdown 结构

```md
# 第一幕 罗马式咖啡馆

## 本幕剧情

林墨：调查失踪案，发现关键线索 X。
苏婉：向玩家隐瞒真实目的，诱导玩家前往旧宅。
陈警官：提供官方文件，引导玩家前往地点 Y。

### 主要剧情
...

### 关键节点
...

### 分支与结局
...
```

### 6.4 渲染

- 人物行动摘要中的每个人名自动包裹为实体链接。
- 不加"本幕涉及人物："前缀。

## 7. Markdown 编辑器增强

### 7.1 工具栏扩展

在 `book-editor.tsx` 现有工具栏上增加按钮组：

```
[ 撤销 ] [ 重做 ]
[ H1 ] [ H2 ] [ H3 ] [ H4 ] [ H5 ] [ H6 ]
[ 粗体 ] [ 斜体 ] [ 下划线 ] [ 删除线 ]
[ 无序列表 ] [ 有序列表 ] [ 引用 ] [ 分隔线 ]
[ 表格 ] [ 图片 ]
[ 字体 ▾ ]
```

### 7.2 格式命令实现

使用现有 `document.execCommand` 完成浏览器稳定支持的基础命令；字体、受控 HTML、表格和图片使用 Selection/Range 与 DOM API 手动插入，随后统一序列化：

| 功能 | 实现方式 |
|---|---|
| 粗体 | `document.execCommand("bold")` |
| 斜体 | `document.execCommand("italic")` |
| 下划线 | `document.execCommand("underline")` |
| 删除线 | `document.execCommand("strikeThrough")` |
| 标题 | 将当前块包裹为 `<h1>`–`<h6>` |
| 无序列表 | `document.execCommand("insertUnorderedList")` |
| 有序列表 | `document.execCommand("insertOrderedList")` |
| 引用 | 当前块包裹 `<blockquote>` |
| 分隔线 | 插入 `<hr>` |
| 表格 | 插入固定 HTML `<table>` |
| 图片 | 插入 `<img src="...">` |
| 字体 | 对选区包裹 `<span data-font="serif|sans|kai">` |

### 7.3 HTML ↔ Markdown 双向转换

- 下划线在 Markdown 中不原生支持，使用 `<u>文本</u>` 保留。
- 字体切换使用白名单 `data-font` 标记保留。
- 表格转换为 GFM 表格语法。
- 图片转换为 `![alt](src)`。
- H4–H6 使用对应数量 `#`。
- 人物卡指令在可视化模式中转换为不可拆散的原子节点，保存后恢复原指令。
- 增加 round-trip 测试，保证 Markdown → HTML → Markdown 不丢失新增格式。

### 7.4 图片上传

- 使用 `<input type="file" accept="image/*">` 选择图片。
- 使用原生 canvas 把最长边限制到 1600px，并将压缩后单图控制在约 1MB 内。
- 读取为 Data URL 嵌入 Markdown；不得持久化 blob URL。
- URL 图片只接受 http/https，Data URL 只接受受控 `data:image/*`。

### 7.5 涉及文件

| 文件 | 改动 |
|---|---|
| `app/components/book-editor.tsx` | 工具栏扩展、命令实现、字体下拉 |
| `lib/markdown.ts`（如存在）或新建 | HTML 与 Markdown 双向转换函数增强 |
| `app/globals.css` | 编辑器工具栏、表格、图片样式 |

## 8. 实体资料窗口重构为浮动便利贴

### 8.1 方案

`entity-window.tsx` 不再由触发文字渲染内联窗口，改为在 `page.tsx` 顶层维护一个浮动窗口栈，用 `position: fixed` 或相对于 `.book-reader` 的绝对定位渲染。

### 8.2 数据结构

```ts
type FloatingEntityWindow = {
  id: string;              // 唯一窗口 ID
  entityRef: string;       // 使用 kind:id，避免不同类型 id 冲突
  x: number;
  y: number;
  width: number;
  zIndex: number;
};
```

### 8.3 状态管理

- 在 `page.tsx` 中维护 `entityWindows: FloatingEntityWindow[]`。
- 点击实体名称时传入触发元素 `DOMRect`；新实体创建窗口，同一实体已有窗口则置顶。
- 点击关联实体时替换当前窗口内容（单历史栈），保留窗口位置。
- 关闭窗口时从数组中移除。
- 离开阅读视图、切换项目或进入编辑器时清空窗口数组。

### 8.4 拖拽实现

```ts
function useDraggable(elRef: RefObject<HTMLElement>, onMove: (x, y) => void) {
  const [dragging, setDragging] = useState(false);
  const start = useRef({ x: 0, y: 0, left: 0, top: 0 });
  // mousedown 记录偏移
  // mousemove 计算新位置
  // mouseup 结束拖拽
}
```

### 8.5 自动位置修正

- 使用 `position: fixed`，默认在触发文字右下方打开。
- 以浏览器视口为边界修正位置；窗口始终保留最小可拖拽标题栏区域。
- 多个窗口错开 24px，避免完全重叠。

### 8.6 涉及文件

| 文件 | 改动 |
|---|---|
| `app/components/entity-window.tsx` | 改为纯内容组件，移除内联定位逻辑 |
| `app/page.tsx` | 管理窗口栈、位置、拖拽、打开/关闭 |
| `app/components/markdown-document.tsx` | 点击实体名称时调用 `onOpenEntity` |
| `app/globals.css` | 浮动窗口、拖拽标题栏、z-index 层级 |

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 编辑器 H4–H6 与现有样式冲突 | 书页标题层级变多，视觉不统一 | 统一定义 h1–h6 字号和行距 |
| 表格过宽撑破书页 | 书页排版错乱 | 表格容器加 `overflow-x: auto`，单元格自动换行 |
| Data URL 图片过大导致 IndexedDB 膨胀 | 项目保存变慢 | canvas 限制 1600px 和约 1MB；超限拒绝保存 |
| 浮动窗口拖拽与 turn.js 翻页事件冲突 | 拖拽窗口时误触发翻页 | 拖拽开始时 `event.stopPropagation()`，阻止冒泡 |
| 多窗口 z-index 管理混乱 | 点击窗口后层级不对 | 每次激活窗口时重新分配递增 z-index |
| 剧本没有明确写出人物行动 | 模型可能臆造动作 | 每个 `personId` 仍返回条目，但标注“本幕无明确行动”；同时保留来源与推断标记 |
| 任意 HTML 引入 XSS | 本地项目被恶意 Markdown 执行脚本 | 标签、属性、字体和 URL 全部白名单化 |
| 旧 `sectionMarkdown` 阻止新模板显示 | 老项目看不到 v0.8 布局 | 不自动覆盖，提供显式应用模板并支持取消 |
