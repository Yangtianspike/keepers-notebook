# V0.8 Spec：书页视觉统一、核心人物重构与编辑器增强

## 目标

在 V0.7.6 统一书页、可视化编辑、实体资料系统的基础上，V0.8 重点解决三类问题：

1. **交互一致性**：所有关键按钮统一为绿边框黑底白字风格。
2. **内容呈现质量**：核心人物/人物经历与动机/幕描述等关键 section 重构，减少信息单薄和重复。
3. **编辑能力增强**：可视化编辑器支持更丰富的 Markdown 格式与字体切换。
4. **模型内容增强**：保持七阶段流程不变，为人物、人物弧线和幕增加向后兼容的可选分析字段。

---

## 1. 按钮风格统一

### 1.1 涉及按钮

| 区域 | 按钮 |
|---|---|
| 分析流程顶部 | 分析剧本、重新分析、分析记录 |
| 剧本解析工具条 | 上一页、下一页、跳页、编辑书页、幕树 |

### 1.2 视觉规范

```css
/* .cb-action-button */
background: rgba(0, 0, 0, 0.85);

color: #ffffff;
border-radius: 6px;

/* hover */
background: rgba(52, 211, 153, 0.15);

```

### 1.3 行为

- 所有上述按钮使用同一组件或同一 CSS 类，避免各自维护样式。
- 禁用状态保持可读，不变成完全灰色。
- 幕树按钮在非幕 section 隐藏，但仍继承相同样式。

## 2. 核心人物 section 重构

### 2.1 需求

- 核心人物阶段（`stage-characters`）需要展示**所有人物**。
- 但人物要按重要程度分类，**核心人物优先且展示更详细**。
- 人物属性（外貌、性格、动机、秘密、状态等）使用**表格形式**展示。

### 2.2 分类规则

| 类别 | 判断依据 | 展示形式 |
|---|---|---|
| 核心人物 | `importance === "core"` 或出场关键度高 | 完整卡片，含头像占位、姓名、身份、属性表格、一句话概述 |
| 重要人物 | `importance === "important"` | 中等卡片，含姓名、身份、关键属性 |
| 次要人物 | 其他 | 紧凑列表，仅姓名、身份、一句话 |

### 2.3 核心人物卡片字段（表格）

| 字段 | 说明 |
|---|---|
| 身份 | 人物在故事中的身份 |
| 外貌 | 外貌特征 |
| 性格 | 性格关键词或简述 |
| 动机 | 当前核心动机 |
| 秘密 | 隐藏信息或真相 |
| 状态 | 初始状态/可变化状态 |
| 扮演提示 | 给 KP 的扮演建议 |

空字段在阅读时不显示，进入编辑模式后可填写。

### 2.4 CoC 7版人物数据

核心人物和非核心人物都允许保存 CoC 7版数据：STR、CON、SIZ、DEX、APP、INT、POW、EDU、HP、MP、SAN、幸运、MOV、体格、伤害加值、护甲、技能和攻击。

- 原剧本存在数值时，模型必须优先提取并标记为 `source`。
- 原剧本没有数值时，允许模型根据身份、年龄和剧情作用生成适用数值，但必须标记为 `inference`。
- 不允许把推断值伪装成原作数据。
- KP 可以编辑全部数值；KP 覆盖层优先于重新分析结果。
- 核心人物默认展示完整数据；重要人物展示主要属性、关键技能和攻击；次要人物使用紧凑展示，但仍可打开完整资料。

### 2.5 交互

- 点击人物名称打开实体资料窗口。
- 核心人物卡片提供"查看完整资料"入口。
- 实体资料窗口中可直接编辑该人物。

## 3. 人物经历与动机 → 核心人物与动机

### 3.1 改名

原 `stage-characterArcs` 显示名称改为：**核心人物与动机**。

### 3.2 内容重构

- 本 section 只聚焦**核心人物**（与 2.2 中"核心人物"一致）。
- 每个核心人物展示：
  - 成长弧线（从故事开始前的状态到故事中的变化）。
  - 动机变化（初始动机 → 事件推动后的动机）。
  - 与故事主线的关系（为什么这个人物对剧情不可或缺）。
- 模型在现有 `characterArcs` 阶段自动生成以上内容；旧数据缺少新增字段时使用现有 `experience`、`motivation` 兼容显示。

### 3.3 Markdown 生成

默认 Markdown 结构：

```md
## 林墨

### 成长弧线
...

### 动机
- **初始动机**：...
- **变化节点**：...
- **最终动机**：...

### 与主线关系
...
```

## 4. 开篇钩子扩充

### 4.1 目标

解决开篇钩子内容单薄的问题，同时避免与序幕剧情重复。

### 4.2 内容边界

| 模块 | 职责 | 内容示例 |
|---|---|---|
| **开篇钩子** | GM 如何开场、如何导入玩家 | 开场朗读文本、导入技巧、初始冲突触发 |
| **序幕** | 玩家实际经历的剧情 | 场景、对话、事件 |

### 4.3 默认字段

1. **GM 开场朗读文本**：可直接读给玩家的第一段描述。
2. **玩家初始处境**：玩家角色在故事开始时的位置和状态。
3. **第一个冲突触发方式**：什么事件把玩家拉进主线。
4. **氛围与感官描写建议**：光线、气味、声音等氛围关键词。
5. **导入技巧**：如何自然地把玩家目标与事件挂钩。

### 4.4 模型生成

- 继续保留现有 `openingHook: string`，兼容旧项目和旧响应。
- 在现有 openingHook 阶段新增可选 `openingHookDetails`，由模型直接生成上述五个字段。
- 新项目默认模板优先读取 `openingHookDetails`；字段缺失时，把旧 `openingHook` 放入“GM 开场朗读文本”，其余字段留空供 KP 编辑。
- 提示词必须区分“主持人导入建议”和“玩家实际经历的序幕剧情”，避免重复复述序幕。

## 5. 幕章节命名去重

### 5.1 规则

- 如果模组本身已经包含"序幕"、"第一幕"、"第二幕"等字样，默认标题不再加"序幕·"、"第一幕·"前缀。
- 只有原始标题明确包含"序幕"时才显示为序幕，不根据数组第一项自动推断序幕。
- 没有幕前缀但有标题时，使用 `第 {act.sequence} 幕 · 原标题`。
- 没有标题时，使用 `第 {act.sequence} 幕`。
- 序幕不编号；普通第一幕保持"第 1 幕"。

### 5.2 示例

| 模组原文 | 默认显示 |
|---|---|
| 序幕：雨夜来信 | 序幕：雨夜来信 |
| 第一幕 罗马式咖啡馆 | 第一幕 罗马式咖啡馆 |
| 雨夜来信（sequence=1） | 第 1 幕 · 雨夜来信 |
| （无标题，sequence=1） | 第 1 幕 |

## 6. 幕描述改名 + 加长

### 6.1 改名

原"幕描述"改为：**本幕剧情**。

### 6.2 加长内容

在原有幕描述前面增加一段**人物行动摘要**：

- 从本幕涉及人物中自动提取每个人物在本幕的关键动作。
- 模型在现有 `acts` 阶段读取该幕相关原文，为每个 `personId` 生成 `personActions`。
- 每条行动摘要必须带来源页码/短引用，或明确标记为模型推断。
- 不加"本幕涉及人物："等前缀标题，直接逐条列出。
- 模型必须覆盖本幕全部 `personIds`；没有明确行为时写明"仅确认出场，未发现具体行动"，不得编造。
- 语言简洁，每个动作一句话。

### 6.3 默认 Markdown 结构

```md
## 本幕剧情

林墨：调查失踪案，发现关键线索 X。
苏婉：向玩家隐瞒真实目的，诱导玩家前往旧宅。
陈警官：提供官方文件，引导玩家前往地点 Y。

### 主要剧情
（原有幕描述内容）

### 关键节点
...

### 分支与结局
...
```

### 6.4 编辑

- 人物行动摘要可由 KP 手动调整。
- 摘要中的人物名称自动识别为实体链接。
- 旧项目没有 `personActions` 时，客户端从 `act.description` 中提取包含人物名的句子作为兼容兜底。

## 7. Markdown 编辑器增强

### 7.1 新增格式工具

在现有工具栏基础上增加：

| 按钮 | 作用 |
|---|---|
| 斜体 | `*文本*` 或 `_文本_` |
| 下划线 | `<u>文本</u>`（Markdown 不原生支持，使用 HTML 标签） |
| 删除线 | `~~文本~~` |
| H1–H6 | 一级到六级标题 |
| 表格 | 插入默认 3×3 表格，可在编辑器中直接调整 |
| 图片 | 插入图片 URL 或本地上传 |
| 字体切换 | 切换当前段落/选区字体 |

### 7.2 字体切换

提供三种字体：

| 名称 | 字体栈 |
|---|---|
| 默认宋体 | `"Noto Serif SC", "Source Han Serif SC", "SimSun", serif` |
| 无衬线 | `"Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", sans-serif` |
| 楷体/手写 | `"KaiTi", "STKaiti", "楷体", serif` |

- 字体切换通过 `data-font-family` 或内联 style 保存在生成的 HTML/Markdown 中。
- Markdown 中使用 HTML 标签 `<span style="font-family:...">` 包裹选区。
- 阅读模式正常解析渲染。

### 7.3 表格编辑

- 默认插入 3 行 3 列表格。
- 编辑器中可直接输入单元格内容。
- 表格宽度适应书页文本框。

### 7.4 图片

- 图片 URL：直接粘贴或输入。
- 本地上传：经 canvas 压缩后读取为 Data URL，存入项目。
- 图片最大宽度限制为文本框宽度，不撑破书页。

### 7.5 图片和 HTML 安全边界

- 持久化只允许 Data URL；blob URL 不写入项目，因为刷新后会失效。
- 本地图片使用原生 canvas 压缩，最长边不超过 1600px，压缩后单图目标不超过 1MB；超限时阻止保存并提示用户。
- 图片 URL 只允许 `https:`、`http:` 和受控的 `data:image/*`。
- 内嵌 HTML 使用白名单，只允许格式化所需的 `u`、字体标记、表格和图片节点；删除脚本、事件属性和危险 URL。

## 8. 实体资料窗口重构

### 8.1 显示逻辑修正

- 不再把资料窗口嵌入到触发文字下方的文档流中。
- 改为**浮动面板**，覆盖在书页上方。
- 默认出现在触发文字右下方，但如果会超出书页可视区域，则自动调整到左上方或屏幕内可用位置。

### 8.2 可拖动便利贴

- 鼠标按住标题栏可拖动窗口位置。
- 窗口位置使用 `position: fixed` 或相对于 `.book-reader` 的绝对定位。
- 拖动后窗口保持在书页上方，不随翻页滚动消失。
- 打开多个实体窗口时，每个窗口独立定位，可叠放。
- 重复打开同一实体时置顶已有窗口，不创建重复窗口。
- 离开书页阅读、切换项目或进入编辑模式时关闭浮动窗口，避免跨视图残留。

### 8.3 默认内容增强

每个实体资料窗口默认显示：

1. **标题区**：实体名称 + 类型标签 + 来源标签。
2. **基础属性表格**：根据实体类型显示对应字段。
3. **描述/正文**：完整 `playerVisible` 内容。
4. **KP 备注**：`keeperPrivate` 内容（仅 KP 可见）。
5. **相关实体**：
   - 自动列出与本实体有直接关联的其他实体。
   - 每个关联实体显示名称和关系类型。
   - 点击关联实体在当前窗口中打开（单历史栈，可返回）。
6. **出现位置**：列出该实体在哪些 section/幕中出现。

### 8.4 所有实体必须有关联实体

- 如果一个实体暂时没有关联实体，显示"暂无关联实体"并提供一个"新建关联实体"入口。
- 不允许出现没有任何关联入口的空白资料窗口。

## 9. 实体资料窗口关联实体增强

### 9.1 人物实体必须显示相关实体

- 人物实体的相关实体包括：
  - 同一幕中直接关联的线索、地点、事件。
  - KP 手动建立的人物—人物关系。
  - 推断关系（如果分析协议提供）。

### 9.2 其他实体同理

- 线索：关联人物、地点、事件。
- 地点：关联人物、线索、事件。
- 事件：关联人物、地点、线索。
- 自定义：根据 KP 手动关联显示。

## 10. 不做的事

1. 不替换 turn.js 翻页引擎。
2. 不引入第三方富文本编辑器（继续使用自研可视化编辑器）。
3. 不改变模型 API action、七阶段顺序、暂停确认和整体分析控制流；允许给现有阶段增加向后兼容的可选输出字段和提示词。
4. 不新增"组织"实体模板。
5. 不做真正的 PDF 导出为可编辑文档。
6. 不修改左侧菜单整体风格和桌面背景。

## 11. 数据结构与旧项目兼容

新增字段全部为可选字段，不升级 IndexedDB schema：

```ts
type PersonCoCStats = {
  str?: number; con?: number; siz?: number; dex?: number;
  app?: number; int?: number; pow?: number; edu?: number;
  hp?: number; mp?: number; san?: number; luck?: number; mov?: number;
  build?: number; damageBonus?: string; armor?: string;
  skills?: Array<{
    name: string; value: number;
    provenance: "source" | "inference";
    sources?: SourceRef[];
  }>;
  attacks?: Array<{
    name: string; value?: number; damage: string;
    range?: string; attacksPerRound?: string;
    provenance: "source" | "inference";
    sources?: SourceRef[];
  }>;
  fieldProvenance?: Partial<Record<
    "str" | "con" | "siz" | "dex" | "app" | "int" | "pow" | "edu" |
    "hp" | "mp" | "san" | "luck" | "mov" | "build" | "damageBonus" | "armor",
    { provenance: "source" | "inference"; sources?: SourceRef[] }
  >>;
};

type Person = {
  // 原字段保留
  summary?: string;
  appearance?: string;
  personality?: string;
  state?: string;
  performanceHints?: string;
  cocStats?: PersonCoCStats;
};

type CharacterArc = {
  personId: string;
  experience: string;
  motivation: string;
  motivationChanges?: {
    initial: string;
    turningPoints: string[];
    final: string;
  };
  mainlineRelation?: string;
};

type ActPersonAction = {
  personId: string;
  summary: string;
  provenance: "source" | "inference" | "none";
  sources: SourceRef[];
};

type OpeningHookDetails = {
  readAloud?: string;
  initialSituation?: string;
  firstConflict?: string;
  atmosphere?: string;
  introductionTips?: string;
};

type Act = {
  // 原字段保留
  personActions?: ActPersonAction[];
};

type Analysis = {
  // 原字段保留
  openingHook: string;
  openingHookDetails?: OpeningHookDetails;
};
```

人物卡 Markdown 只保存实体引用和布局元数据，实际字段始终从 `original + overrides` 动态读取，避免实体修改与书页副本不同步。

已经存在的 `sectionMarkdown` 不自动覆盖。新项目使用 v0.8 模板；旧项目提供显式“应用 v0.8 模板”操作，用户确认后才替换对应 section。模板切换前保留当前草稿，取消操作不得修改项目。

## 12. 验收标准

### 12.1 按钮风格

- [ ] 分析流程三个按钮和分析记录按钮样式一致（绿边框黑底白字）。
- [ ] 剧本解析工具条五个按钮样式一致。
- [ ] 按钮 hover、disabled、focus 状态统一。

### 12.2 核心人物重构

- [ ] 核心人物阶段展示所有人物。
- [ ] 人物按重要程度分类显示。
- [ ] 核心人物使用卡片 + 属性表格展示。
- [ ] 人物属性表格包含身份、外貌、性格、动机、秘密、状态、扮演提示。
- [ ] 核心人物显示完整 CoC 数据；非核心人物可打开完整 CoC 数据。
- [ ] 原文数值标记为剧本资料，模型补全数值标记为模型推断。
- [ ] KP 修改 CoC 数据后重新分析不会覆盖 KP 修改。
- [ ] 点击人物名称可打开实体资料窗口。

### 12.3 核心人物与动机

- [ ] 阶段名称改为"核心人物与动机"。
- [ ] 只展示核心人物的成长弧线、动机变化、与主线关系。
- [ ] 内容与人物实体联动，修改实体后同步。
- [ ] 新分析自动生成动机变化和主线关系；旧数据使用兼容显示。

### 12.4 开篇钩子

- [ ] 开篇钩子包含 GM 开场朗读文本、玩家初始处境、第一个冲突触发方式、氛围描写建议、导入技巧。
- [ ] 内容与序幕不重复。

### 12.5 幕章节命名

- [ ] 模组已写"序幕/第一幕"时，不再添加默认前缀。
- [ ] 无标题幕使用"第 N 幕" fallback。

### 12.6 本幕剧情

- [ ] "幕描述"改名为"本幕剧情"。
- [ ] 本幕剧情前增加人物行动摘要。
- [ ] 摘要不加前缀标题，直接列出人物动作。
- [ ] 每个 `personId` 都有行动条目；原文没有明确行动时标注“本幕无明确行动”，不凭空补写。
- [ ] 每条人物行动包含来源或明确的推断标记。

### 12.7 Markdown 编辑器增强

- [ ] 斜体、下划线、删除线可用。
- [ ] 标题支持 H1–H6。
- [ ] 可插入表格并编辑内容。
- [ ] 可插入图片（URL 或本地上传）。
- [ ] 可切换字体，保存后阅读模式正确显示。
- [ ] 超限图片被压缩或拒绝，不把 blob URL 保存进项目。
- [ ] 危险 HTML、脚本和事件属性不会进入阅读 DOM。

### 12.8 实体资料窗口

- [ ] 资料窗口以浮动面板显示，不嵌入文档流。
- [ ] 窗口可被拖动。
- [ ] 默认显示完整字段、KP 备注、相关实体、出现位置。
- [ ] 所有实体至少显示"相关实体"区域和新建关联入口。
- [ ] 点击关联实体在同一窗口中打开，可返回。
- [ ] 重复打开同一实体时置顶原窗口。
- [ ] 离开书页或进入编辑模式后浮动窗口关闭。
