# V0.8 Task：任务拆分与开发顺序

## 执行规则

- 按 T1 → T11 串行执行，前一项验证通过后再进入下一项。
- 每项一个独立 commit，不混入历史未跟踪文档或无关改动。
- 不改变模型 API action、七阶段顺序、暂停确认和整体分析控制流。
- 新增分析字段全部可选；旧项目必须可以直接载入。
- 前六阶段和所有幕继续共用同一个 pages 数组和 turn.js 实例。

---

## T1：建立共享 Markdown AST、转换与安全层

**依赖**：无。

**文件**：新建 `lib/markdown.ts`，修改 `app/components/markdown-document.tsx`，新增 Markdown 单元测试。

**步骤**：

1. 定义 heading 1–6、paragraph、list item、quote、divider、table、image、character directive 等 block。
2. 定义 bold、italic、strike、underline、font token、keeper link 等 inline。
3. 把现有解析、Markdown → 编辑 HTML、编辑 HTML → Markdown 迁移到共享模块。
4. 字体仅接受 `serif|sans|kai`；HTML 标签、属性和 URL 使用白名单。
5. 图片仅允许 http、https 和受控 data:image。
6. 保证人物指令在可视化编辑中是原子节点并可 round-trip。

**验证**：新增格式往返测试通过；`script`、`onerror`、`javascript:` 被移除；lint/build 通过。

## T3：扩充人物、人物弧线和幕的模型输出

**依赖**：无。

**文件**：`lib/types.ts`、`app/api/model/route.ts`、`app/page.tsx`、`lib/entities.ts`。

**步骤**：

1. 新增可选 `PersonCoCStats`，包含完整 CoC 7版属性、技能与攻击；每项保留独立 provenance/sourceRefs。
2. 给 Person 增加 summary、appearance、personality、state、performanceHints、cocStats。
3. 保留 `openingHook: string`，增加可选 openingHookDetails 五字段对象。
4. 给 CharacterArc 增加 motivationChanges、mainlineRelation，保留 experience、motivation。
5. 给 Act 增加可选 personActions，包含 personId、summary、`source | inference | none` provenance、sources。
6. 更新 characters 提示词：优先提取原文数值；缺失时允许推断并逐项明确标记。
7. 更新 openingHook 提示词：生成五部分内容且不复述序幕。
8. 更新 characterArcs 提示词：输出动机变化和主线关系。
9. 更新 acts 提示词：覆盖全部 personIds，基于幕原文总结行动并保留来源；无明确行动不得编造。
10. 客户端解析新增字段时做类型归一化；字段缺失时保持旧逻辑。

**验证**：旧 JSON 可载入；新数据逐项保留 source/inference，空行动保留 none；openingHook 新旧响应均可解析；异常数值不破坏项目；API action 与阶段顺序未改变。

## T4：默认模板构建器与幕标题规则

**依赖**：T3。

**文件**：`lib/entities.ts`、`app/page.tsx`，新增模板单元测试。

**步骤**：

1. 新增 `buildCharacterMarkdown(project)`，按 core/important/minor 生成实体引用指令。
2. 新增 `buildCharacterArcsMarkdown(project)`，只包含核心人物。

6. 旧 Act 没有 personActions 时，从 description 提取人物句子并兜底。

**验证**：标题四类测试通过；开篇钩子始终有五个标题；每个 act.personIds 都有行动条目。
