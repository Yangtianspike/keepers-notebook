# 守秘人图谱 v0.8.1 补丁

## 背景

v0.8 完成人物 CoC 数据、可视化编辑、实体资料窗口和增强书页模板后，实际使用暴露出人物阶段输出过长、战斗数据召回不足、书页实体菜单被裁切、人物关系缺乏语义，以及项目导航仍不像一本可持续编辑的模组笔记本等问题。

本补丁收纳 v0.8 完成后讨论并确认的全部改动。未列入本文的后续想法不在本补丁中顺手实现。

## 已确认的产品决定

1. 保持现有七阶段分析架构，不新增后台自动分析阶段。
2. 所有人物都允许拥有 CoC 7 版属性；原文明示值标记 `source`，缺失值可推断但必须标记 `inference`。
3. 旧项目打开时不得自动调用模型。人物语义关系只在用户主动重新分析后生成。
4. “核心人物”章节统一改名为“人物”，“核心人物与动机”改名为“人物经历与动机”。
5. “剧本解析”导航组改名为“模组笔记本”。
6. 模组笔记本目录收录 H1～H6 全部标题，按正文顺序形成可折叠树。
7. 左侧栏采用“完全隐藏 / 完整展开”，不保留缩窄图标栏。
8. 多张实体资料卡可以与书页同时存在；跳转书页、切换项目内部页面时不自动关闭。

---

## F1：人物分析输出稳定性与 CoC 专项召回

### 问题

v0.8 要求一次返回所有人物及完整 CoC 属性、技能、攻击和逐字段来源，人物较多时容易超过模型输出上限，最终得到被截断的 JSON。人物阶段原检索词也没有覆盖“战斗、力量、技能、HP、NPC、守秘人笔记”等数据页。

### 修复

- 人物阶段先生成紧凑人物索引，再按每批最多六人补全详情与 CoC 数据。
- 人物索引阶段保留用户选择的三档确认模式；详情批次不重复触发确认工具。
- 人物检索增加属性、战斗、技能、攻击、NPC 和守秘人数据关键词。
- 除常规人物外，明确识别无姓名的 NPC 群体、敌人模板和守秘人建议数据。
- 对输出达到上限、遗漏人物、非法 JSON 分别给出可操作错误。
- `60% (30/12)` 当前保存基础值 60；困难与极难值可由规则计算，不新增重复字段。

### 验收

- 人物较多时不再依赖单个超大 JSON。
- 中文“力量、体质、灵感、战斗、技能”等内容能进入人物阶段上下文。
- 原文没有完整数据的人物仍生成推断属性并正确标记。

## F2：人物语义关系与行动轨迹

### 问题

当前人物关系主要来自“同见于第 X 幕”，只能证明共同出现，不能解释人物之间的逻辑关系。资料卡也缺少人物在整个剧本中的行动概览。

### 修复

- 在“人物经历与动机”阶段返回可选 `personRelations`：
  - 起点人物、终点人物；
  - 有方向的简短关系标签；
  - 关系摘要；
  - 重要程度；
  - `source | inference` 来源标记与原文引用。
- 同一人物对存在多种关系时，资料卡默认只显示优先级最高的一条。
- 人物与人物之间不再展示“同见于第 X 幕”。共同出场仍可在内部用于召回，但不作为可见语义关系。
- 人物资料卡新增“剧本行动轨迹”，组合人物经历与各幕 `personActions`，按幕顺序展示行为及来源标记。
- 旧项目没有 `personRelations` 时不自动调用模型；用户主动重新分析后补齐。

### 验收

- 人物关系显示“领导、雇佣、威胁、保护、协作”等实际语义。
- 没有语义依据时不显示虚构关系。
- 人物资料卡能查看其全剧本经历与逐幕行动。

## F3：实体链接菜单不再被书页裁切

### 问题

书页中的“跳转 / 打开资料窗口”菜单位于 turn.js 页面 DOM 内，受到页面 `overflow` 裁切；靠近右页边缘时只能显示一部分。提高 `z-index` 无法突破父级裁切。

### 修复

- 使用 React Portal 把实体操作菜单挂到 `document.body`。
- 使用 viewport fixed 坐标对齐触发文字。
- 根据视口空间自动向左、向右、向上或向下展开。
- 点击外部、滚动、翻页、窗口缩放和组件卸载时关闭菜单。
- Portal 节点不交给 turn.js 管理。

### 验收

- 左右书页边缘的实体菜单完整可见。
- 菜单不会造成 turn.js DOM 层级异常。

---

## F4：多实体资料卡工作台

### 问题

点击关联实体时，当前实现替换原窗口中的实体；跳转书页时还会清空所有资料卡，无法形成边读边查的工作台。

### 修复

- 点击关联实体新建独立资料窗口，原窗口保留。
- 同一实体只打开一个窗口；重复打开时将已有窗口置顶。
- 新窗口自动错位，并限制在当前视口内。
- 每张窗口可独立拖动、编辑和关闭。
- 跳转书页或切换项目内部视图时保留资料卡。
- 返回项目选择首页或切换到另一个项目时清空资料卡。
- 顶栏显示当前资料卡数量并提供“全部关闭”。

### 验收

- 人物 A 的资料窗口中打开人物 B 后，A、B 同时存在。
- 书页翻页、章节跳转和原始资料视图不会清空窗口。
- 重复打开同一实体不会产生重复窗口。

## F5：人物章节分层展示

### 修复

- 人物章节主体优先展示核心人物完整卡片。
- 增加“全部人物索引”，按核心、重要、次要人物分组。
- 重要和次要人物通过索引及相关人物资料卡访问，不再连续铺满大量完整书页卡片。
- 点击人物卡或索引项打开羊皮纸资料窗口。
- 关系探索通过多个独立资料窗口递进，不在固定书页中动态展开嵌套卡片，避免破坏分页。

### 验收

- 人物章节首先呈现核心人物。
- 任意重要或次要人物仍可从索引访问。
- 打开关系资料不会改变书页高度或触发重新分页。

---

## F6：模组笔记本动态多级目录

### 修复

- “剧本解析”更名为“模组笔记本”。
- H1～H6 全部进入左侧目录。
- 目录按整本书的真实标题顺序构建。
- 有子标题的条目显示无边框折叠三角：`▸` 收起、`▾` 展开。
- 点击三角只控制展开；点击标题让同一个 turn.js 实例跳到标题所在页。
- 当前页对应标题及其祖先自动高亮、展开。
- 编辑后标题新增、删除、改名以及分页变化都会重新计算目录和页码映射。
- 深层标题保留层级关系，但侧栏缩进设置上限以保证可读宽度。

### 验收

- 用户新增任意级别标题后，保存返回书页即可在目录中看到。
- 自定义标题出现在正文实际位置，不统一追加到末尾。
- 点击任一标题能跳到正确页，仍使用同一 pages 数组与 turn.js 实例。

---

## F7：顶部栏与左侧导航重构

### 修复

- 顶部栏左侧提供 Home 和菜单按钮。
- Home 返回外部项目选择首页。
- 菜单按钮控制左侧栏完全隐藏或完整展开；工作区宽度同步变化。
- 展开状态保存在当前浏览器。
- 书页模式下把上一页、页码、跳页、编辑书页、幕树、下一页融合到全局顶部栏。
- 删除左侧所有菜单项前方的带框小图标。
- 保留“前期准备、模组笔记本、原始资料”三组，并增加组间距。
- 三个组标题字号和字重略高于组内项目。
- 当前项目使用文字颜色、淡色背景和左侧高亮线表示。
- 项目尚未产生分析结果时，模组笔记本只显示已经可阅读的章节；外部项目选择首页不显示项目内部导航。

### 验收

- 侧栏隐藏后工作区利用全部宽度，再次点击可恢复。
- 刷新后保留侧栏展开状态。
- 左侧不再出现带框字符图标。
- 书页控制在顶部同一水平线上并保持键盘翻页能力。

## 数据结构

新增字段保持可选，不提升 IndexedDB schema：

```ts
type PersonRelation = {
  id: string;
  sourcePersonId: string;
  targetPersonId: string;
  label: string;
  summary: string;
  importance: "primary" | "secondary";
  provenance: "source" | "inference";
  sources: SourceRef[];
};

type ProjectAnalysis = {
  personRelations?: PersonRelation[];
};
```

目录标题与页码从当前 Markdown 和 DOM 分页结果派生，不持久化易失页码。

## 不在本补丁范围

- 不新增组织实体模板。
- 不新增第八个分析阶段。
- 不在打开旧项目时自动调用模型。
- 不替换 turn.js，不拆分统一 pages 数组。
- 不实现完整全局人物关系图。
- 不引入第三方富文本编辑器或导航组件。

### 浏览器实测

- 实体操作菜单父节点为 `BODY`，不在 `.flipbook` 内，完整落在 1280×720 视口中。
- 左侧栏收起后位移 `-218px`，工作区左边距变为 `0px` 并扩展到视口宽度。
