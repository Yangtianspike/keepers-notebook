# V0.9 Plan：技术设计

## 1. 基线与原则

1. 以当前仓库为准：Next.js 16.2.6、React 19.2.6、vinext/Vite、turn.js 1.0.5。
2. 固定逻辑分页，显示层响应式缩放；不能因 resize 改变 Markdown 分页。
3. 人类 Boss 只有一份 `person` 实体；章节通过引用复用。
4. 编辑器位于 turn.js 外部的模态覆盖层，避免克隆 DOM 的局部 state 和层级异常。
5. 旧数据只读兼容，不做破坏性清理。

## 2. 序幕与分析流程

### 2.1 删除独立阶段

从阶段常量、分析进度、分析目标、默认 Markdown、导航和结果查看中删除 `stage-openingHook`。服务端/客户端阶段编排同步调整，不再请求独立开篇钩子。

幕分析 schema 直接包含序幕。页面结构继续使用多个 section 组成同一个 pages 数组：

```text
acts:prologue  -> # 幕 / ## 序幕
acts:<actId>   -> ## 第 1 幕 · ...
acts:<actId>   -> ## 第 2 幕 · ...
```

不把所有幕拼成单一 `buildActsMarkdown`，从而保留既有每幕独立保存、目录跳转和编辑能力。

### 2.2 兼容解析

新增纯函数 `resolvePrologueMarkdown(project)`：

1. `sectionMarkdown["acts:prologue"]`
2. `sectionMarkdown["stage-openingHook"]`
3. `analysis.openingHookDetails`
4. `analysis.openingHook`

返回内容先规范标题，移除旧的顶级“开篇钩子”标题，再包入 `# 幕` 和 `## 序幕`。只选择一个来源，避免重复。没有其他幕也生成 `acts:prologue`。

## 3. 怪物/Boss 数据适配

### 3.1 类型

- `EntityKind` 增加 `monster`。
- `Person` 增加可选 `isBoss`。
- `ProjectAnalysis` 增加可选 `monsters?: Monster[]`。
- `Act` 增加可选 `monsterIds?: string[]`。
- `Monster` 复用现有实体基础字段、图片、关系和 `PersonCoCStats`，避免 `db`/`damageBonus`、数字/字符串 armor 等键名冲突。

### 3.2 模型适配

人物索引结果改为 `{ people, monsters }`。两个列表分别分批拉取详情、normalize、merge；统一做标准化名称/别名去重，并阻止同一实体进入两个集合。

分类规则写入提示词与后处理：

- 有姓名的人类/类人 Boss → `people[].isBoss = true`
- 非人怪物、神话生物、野兽、无名敌人模板 → `monsters[]`

若模型错分，以后处理规则修正；不采用 `person + isMonster` 作为最终数据。

## 4. 章节和核心卡片复用

新增 `stage-monsters` section，数据源为：

```ts
const bossPeople = people.filter((person) => person.isBoss);
const entries = [...bossPeople, ...(analysis.monsters ?? [])];
```

提取通用 `CoreEntityCard`/卡片 Markdown 构建器，人物、Boss、怪物使用相同布局骨架和语义段：

1. overview：肖像、名称、摘要、身份/类型。
2. details：外貌、性格/行为、动机、秘密、状态、提示、能力与弱点。
3. stats：CoC 属性、技能和攻击。

分页继续通过不可分割语义块测量；单个段超过一页时使用现有安全分块策略，不裁切文本或表格。人类 Boss 传入同一个 person ref，资料卡和覆盖层不会产生副本。

## 5. 书页缩放

### 5.1 布局

```css
.workspace {
  height: 100dvh;
  display: grid;
  grid-template-rows: auto minmax(0, 1fr);
}

.workspace-main.book-workspace-main,
.book-reader,
.stage-view {
  min-height: 0;
  overflow: hidden;
}
```

避免 `calc(100vh - 70px)`，因为当前顶部栏允许自适应高度。

### 5.2 turn.js

`useTurnBook` 仍在 `stage-view.tsx`。用 `ResizeObserver` 读取 reader 实际尺寸，按固定虚拟书页 680×1150、双页逻辑宽度 1360 计算 scale。

- 同一 single/double 模式：调用 turn.js `size`，不销毁实例。
- 跨显示断点：记录 section key、页内逻辑索引/目标页，销毁并重建后恢复。
- resize 使用 debounce，并避开进行中的翻页动画。
- 太小只提示，不用 `Math.max` 强制溢出。

## 6. 浮动资料卡缩放

给每个浮动窗口增加逻辑尺寸和 `scale`。外层负责视觉占位、拖动和 z-index，内层使用 `transform: scale(var(--entity-scale))` 且 `transform-origin: top left`。

```ts
scale = Math.min(
  1,
  (workspaceWidth - margin * 2) / logicalWidth,
  (workspaceHeight - margin * 2) / logicalHeight,
);
```

拖动坐标统一使用视觉像素，resize 后 clamp 到可见区域。资料卡内部分页按逻辑尺寸计算，因此缩放不会重排内容。每张卡独立保存 currentPage、position 和 zIndex。关闭按钮必须始终在可见范围。

## 7. 羊皮纸覆盖编辑层

卡片“编辑”按钮只派发 entity ref，由 page 级状态打开单例 `EntityEditOverlay`：

- portal/固定层位于 turn.js 外部并高于书页和资料卡。
- 复用/抽取 `EntityEditForm`，人物、Boss、怪物共享字段编辑、图片压缩、技能和攻击编辑。
- 保存前构建 draft；只有显式保存才写 `entityOverrides`。
- 取消、遮罩关闭、关闭按钮和 Esc 都丢弃 draft。
- 保存后关闭 overlay，触发统一 repagination，并按 section + logical page 恢复位置。
- reanalysis 只更新原始 analysis，覆盖层继续优先应用。

## 9. 风险控制

| 风险 | 控制 |
|---|---|
| 开篇钩子/序幕重复 | 单一优先级解析；保存后只读新 key |
| 人类 Boss 重复实体 | 章节引用 person ref；跨集合去重测试 |
| turn.js DOM 异常 | 同模式不重建；跨模式严格销毁并恢复逻辑页 |
| resize 回第一页 | 保存 section 与逻辑页，不保存易变 DOM 页号 |
| 编辑影响测量克隆 | 表单完全放在 turn.js 外部 |
| 怪物卡过高 | overview/details/stats 语义分页 |
| 资料卡缩放后不可关闭 | resize clamp，关闭控件可见性测试 |
