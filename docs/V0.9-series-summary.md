## 是否直接发布 v1.0.0

当前代码适合作为 **v1.0.0 候选版（RC）**，暂不建议直接标记为正式 v1.0.0。

原因不是功能数量不足，而是 v0.9.5 刚改变了核心分析状态机：

1. 分析阶段由六阶段升级为七阶段。
2. 怪物/Boss 从人物请求中拆出，并修复了上下文传递缺陷。
3. 实时确认从阻塞覆盖层改为后台继续。
4. 删除项目增加了对异步迟到保存的防护。
5. PDF 书签和 DOCX 图片属于新加入的真实文档兼容路径。

这些能力需要独立验收 agent 和用户真实模组测试，不能只以编译与单元测试作为 1.0 证据。

## v1.0.0 发布门槛

- [ ] 使用至少一个带 PDF 书签的模组完成导入、结构确认和书签重读。
- [ ] 使用至少一个 DOCX 验证原文排版和内嵌图片提取。
- [ ] 使用包含人物、人类 Boss、非人怪物和 CoC 数据块的模组跑完七阶段。
- [ ] 验证人物阶段与怪物/Boss 阶段可以分别失败和单独重跑。
- [ ] 在实时确认模式下至少完成一次暂停、裁决、后台继续和再次确认。
- [ ] 分析运行中返回主菜单并删除项目，等待原请求结束后确认项目不会复活。
- [ ] 验证可视化编辑、turn.js 翻页、目录跳转、实体窗口和关系图的主路径。
- [ ] 对 OpenAI 兼容协议至少完成一次端到端分析；其他协议完成连接和基本响应验证。
- [ ] 执行 `npm run lint`、`npm run build`、`npm run test`，全部通过。
- [ ] 创建独立验收报告，所有阻塞级问题关闭。

## 推荐发布路径

1. 将当前 v0.9.5 作为 v1.0.0-RC1 进行真实模组验收。
2. RC 阶段只修阻塞问题，不增加新功能。
3. 验收通过后更新包版本、发布说明和最终验收报告。
4. 同一代码基线标记 v1.0.0；未通过项另开 v0.9.6 或 RC2 修复。
