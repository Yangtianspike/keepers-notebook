# V0.9 Spec：序幕整合、怪物与 Boss、响应式工作台与卡片编辑

## 目标

V0.9 完成四项能力：

1. 删除独立“开篇钩子”分析阶段，把相关内容作为“序幕”的组成部分。
2. 新增“怪物与 Boss”章节；所有怪物和 Boss 使用核心人物卡规格展示并可编辑。
3. 书页和浮动资料卡都随工作台可用空间自动缩放。
4. 核心人物卡、怪物卡和 Boss 卡通过羊皮纸覆盖编辑层直接编辑，并共享 KP 覆盖数据。

---

## 1. 序幕取代开篇钩子阶段

### 1.1 新项目

- 从分析流程、进度列表、重新分析目标、左侧目录和独立书页中删除“开篇钩子”。
- 幕分析直接产出“序幕”和后续各幕；不再发起独立的开篇钩子请求。
- “序幕”是“幕”一级标题下的第一个二级标题。
- 原开篇钩子的开场朗读、玩家处境、冲突触发、氛围建议和导入技巧，作为序幕正文内容生成，不建立平级阶段。

```md
# 幕

## 序幕

### GM 开场朗读文本
...

### 玩家初始处境
...

### 第一个冲突触发方式
...

## 第 1 幕 · 标题
...
```

### 1.2 旧项目兼容

- 旧 `stage-openingHook` 数据保留，不删除。
- 内容优先级：已保存的序幕 Markdown > 旧 `stage-openingHook` Markdown > 结构化 `openingHookDetails` > 旧 `openingHook`。
- 旧项目没有序幕时，在内存中创建序幕并注入旧内容；已经存在序幕时不得重复追加。
- 用户保存后只写新的序幕内容，旧字段继续保留但不再参与重复渲染。
- 即使项目没有其他幕，只要存在旧开篇钩子内容，也必须能显示“幕 → 序幕”。

## 2. 人物、Boss 与怪物分类

### 2.1 分类规则

- 有姓名的人类或类人 Boss 仍属于 `person`，增加可选 `isBoss: true`。
- 人类 Boss 继续参与人物关系、人物经历、幕行动和所有人物检索。
- “怪物与 Boss”章节引用同一个人类 Boss 实体，不复制第二份实体。
- 非人怪物、神话生物、野兽和无名敌人模板属于 `monster`。
- 同一个对象不得同时出现在 `people` 和 `monsters` 中。

```ts
type EntityKind = "person" | "clue" | "place" | "event" | "custom" | "monster";

type ProjectAnalysis = {
  people: Person[];
  monsters?: Monster[];
};
```

### 2.2 怪物数据

怪物至少支持：名称、别名、类型、威胁等级、摘要、外貌、特殊能力、弱点、战术、奖励、KP 备注、相关幕、相关实体、图片，以及 CoC 7 版属性、技能和攻击。

- CoC 数值复用现有 `PersonCoCStats` 的实际字段和来源结构，不创建不兼容的第二套键名。
- 来源为 `source`、`inference` 或 `keeper`。
- `Act` 可选增加 `monsterIds`，用于幕出现位置和关联解析。
- `keeperPrivate` 只保存在既有私密字段中，不复制到公开字段集合。

### 2.3 AI 输出

- 人物阶段输出两个独立集合：`people` 与 `monsters`。
- 人类 Boss 输出到 `people` 且带 `isBoss`；非人怪物输出到 `monsters`。
- 索引、分批详情、规范化与合并逻辑分别处理两个集合。
- 只提取原文存在的 CoC 数据；缺失值可以明确标记推断，但不得把推断伪装成原文。
- 重复名称或别名必须归并，防止重复怪物及人/怪跨集合重复。

## 3. “怪物与 Boss”章节和卡片规格

- 章节位于“人物”和“人物经历与动机”之间。
- 章节同时展示 `monster` 实体和 `person.isBoss === true` 的人物引用。
- 没有任何怪物或 Boss 时显示“本模组暂无怪物或 Boss”。
- 所有怪物与 Boss 必须使用与核心人物卡相同的完整规格：肖像区、摘要、公开身份/类型、外貌、性格或行为模式、动机、秘密/KP 信息、状态、扮演或运行提示、CoC 属性、技能、攻击、来源标记和编辑入口。
- 内容过长时沿用核心人物卡的语义分段分页，不切断属性表、技能项或攻击项。
- 点击名称仍可打开浮动资料卡；人物 Boss 打开的仍是同一个人物实体。
- 核心人物卡、怪物卡和 Boss 卡均支持上传图片及编辑。

## 4. 书页自适应缩放

- 工作区使用 `100dvh` 和实际顶部栏高度分配空间，不依赖固定 `70px` 推算。
- `ResizeObserver` 监听真实阅读容器尺寸，包括浏览器 resize 与侧栏展开/收起。
- 逻辑分页仍固定使用单页 680×1150；仅显示层按容器等比缩放，不能因缩放改变分页结果。
- 宽度足够时显示双页，不足时显示单页。
- 同一显示模式内只调用 turn.js `size` 调整尺寸；仅跨越单双页断点时重建实例。
- 重建前记录逻辑页，重建后恢复该页；不得回到第一页或破坏目录跳转。
- 空间过小时显示提示，不能通过强制最小宽高制造页面溢出。
- 正常桌面视口下不出现工作区纵向滚动。

---

## 5. 浮动资料卡自适应缩放

- 浮动资料卡使用固定逻辑尺寸和分页容量，避免窗口缩放后内容重新乱分页。
- 根据工作台可用宽高计算不大于 1 的显示比例，并等比缩放资料卡。
- 缩放后标题、正文、图片、按钮和分页控件整体保持比例；仍可拖动、置顶、关闭和翻页。
- 浏览器 resize 或侧栏切换后重新计算比例，并把资料卡位置限制在可见工作区内。
- 多资料卡同时存在时分别保留页码、层级和相对位置，不得因缩放关闭或覆盖其他卡片。
- 视口太小时显示提示，并确保关闭按钮始终可操作。

## 6. 卡片直接编辑

- 核心人物卡、怪物卡与 Boss 卡右上角显示“编辑”。
- 点击后在当前书页上方打开可关闭的羊皮纸模态覆盖层；不在 turn.js 页面或测量克隆 DOM 内直接插入表单。
- 编辑期间保持当前逻辑页和 turn.js 实例稳定，背景书页不可误触。
- 编辑表单复用资料卡现有实体编辑逻辑，支持名称、别名、图片、公开字段、KP 字段、CoC 属性、技能、攻击及链接行为。
- 保存一次性写入 `kpNotes.entityOverrides`，标记 `keeper`，关闭覆盖层后重新分页并恢复原逻辑页。
- 取消、关闭或按 Esc 均不保存。
- 重新分析更新 AI 原始层，但不得覆盖 KP 修改层。
- 书页卡片编辑与浮动资料卡编辑必须即时读取同一份覆盖数据。

---

## 7. 不做的事

1. 不替换 turn.js，不改变桌面背景或左侧菜单整体视觉语言。
2. 不引入第三方富文本编辑器。
3. 不新增“组织”实体。
4. 不导出 PDF。
5. 不删除旧 `stage-openingHook` 持久化数据。
6. 不复制人类 Boss 为 monster 实体。

---

## 8. 技术基线与兼容

- 实际技术栈：Next.js 16.2.6、React 19.2.6、TypeScript、vinext/Vite、turn.js 1.0.5 与 jQuery。
- `useTurnBook` 当前位于 `app/components/stage-view.tsx`，实现时在原位置修改或先安全抽取，不假定存在 `use-turn-book.ts`。
- 前置阶段、怪物与 Boss 章节和所有幕继续共享一个 pages 数组和一个 turn.js 实例。
- 新字段均为可选；除非实际存储结构确实需要，否则不提升 IndexedDB schema 版本。

## 9. 验收摘要

- 独立开篇钩子从分析和 UI 完全消失，旧内容只在序幕出现一次。
- 人类 Boss 与怪物分类正确，无跨集合重复。
- 所有怪物/Boss 使用核心人物卡规格，能编辑、上传图片并正确分页。
- 书页与所有浮动资料卡能随可用空间缩放，保留页码、位置和交互。
- 覆盖编辑层保存、取消、刷新、重新分析均符合覆盖层规则。
- `npm run lint`、`npm run build`、`npm run test` 全部通过。
