# 守秘人笔记本 v1.0.0 Spec

> 状态：已确认，开发完成待验收  
> 基线：v0.9.5  
> 定位：正式版发布候选（RC2）

## 背景

v0.9 系列已经具备七阶段分析、双页书页、Markdown 可视化编辑、实体资料卡、关系图、原始文档与图片资料等主要能力。正式发布 v1.0.0 前，仍需统一 Markdown 与书页目录的层级模型，修复“幕”目录归属、编辑状态恢复和退出定位，并补齐主动创建实体与核心人物卡编辑窗口拖动能力。

## 目标

- Markdown 编辑器与书页共用一套 H1–H6 目录模型。
- “幕”成为稳定的一级目录，各幕及其内部标题保持正确父子关系。
- 编辑过程中跨页面导航不会丢失编辑模式、当前位置或未保存草稿。
- 保存退出后直接回到最后编辑的章节或标题所在书页。
- 用户无需先选择文字，也能主动创建实体资料卡。
- 所有来源的关系变化统一驱动个人关系图和核心人物关系图。
- 核心人物卡的编辑窗口可以在工作台范围内拖动。
- 完成正式版发布所需的回归验证与版本标识更新。

## 功能需求

### F1 H1–H6 统一目录模型

- Markdown 编辑器继续支持创建和修改 H1、H2、H3、H4、H5、H6。
- 编辑器目录和书页左侧目录必须使用同一套标题解析与层级规则，不得分别推断。
- H1 是一级目录；H2–H6 按文档顺序归入最近的、更浅一级标题。
- 当中间层级缺失时，例如 H2 后直接出现 H4，H4 归入最近的 H2，不生成虚构标题。
- 编辑器中标题层级或文字发生变化后，编辑器目录立即更新。
- 保存后，书页目录同步显示最新 H1–H6 层级；新增子标题可展开、收起并跳转到对应内容。
- 重复标题必须使用稳定且互不冲突的定位标识，不能跳到同名标题的错误位置。

### F2 “幕”目录层级修复

- “幕”固定作为模组笔记本中的一级目录。
- 每一幕固定作为“幕”下的二级目录；幕内标题依次使用 H3–H6。
- “幕”目录节点不得寄存在第一幕 Markdown 内容中，也不得因第一幕被编辑、清空、隐藏或缺失而消失。
- 原有各幕的顺序、名称、Markdown 内容和书页定位保持不变。
- 目录中不得再次出现各幕与“幕”并列的错误结构。

### F3 保存退出后的精确定位

- 编辑器持续记录最后一次发生内容修改的章节，以及该章节内最后修改或停留的标题。
- 点击“保存并返回书页”后，进入书页模式并跳到该章节/标题对应的实际书页。
- 如果最后编辑位置无法解析，则降级跳到该章节首页，不得回到整本书第一页。
- 点击“取消”不保存草稿，并返回进入编辑模式前的书页位置。

### F4 跨页面保留编辑会话

- 在 Markdown 编辑模式中进入“前期准备”等非书页页面时，只暂时隐藏编辑器，不结束编辑会话。
- 返回“模组笔记本”后仍处于 Markdown 编辑模式，并恢复活动章节、目录展开状态、编辑模式（可视化/源码）和滚动位置。
- 尚未点击保存的草稿必须保留在当前浏览器会话内，不能因组件卸载而丢失。
- 草稿不在后台自动覆盖正式书页内容；只有用户点击保存后才写入项目数据。
- 用户仍可通过“取消”明确丢弃本次未保存修改。
- 编辑器有未保存修改时显示明确状态；刷新、关闭页面或返回项目首页前提示用户保存或放弃。
- 删除容易误解且与 Enter 等效的“新增段落”按钮；“撤销”和“重做”改为“撤销（Ctrl+Z）”与“恢复撤销（Ctrl+Y）”。

### F5 主动创建实体

- Markdown 编辑器工具栏新增独立的“新建实体”按钮，与现有“关联实体”按钮并列。
- “新建实体”不要求用户预先选择文字。
- 点击后显示实体类型和名称输入；支持项目当前已有的实体类型，不新增组织类型。
- 创建界面允许选择一个或多个已有实体作为关联对象，并为每条关系填写简短的语义关系；不调用模型推断关系。
- 创建成功后立即打开该实体的可编辑资料窗口，使用对应实体模板。
- 如果编辑器中存在有效光标位置，用户可以选择“同时插入实体链接”；启用后在光标处插入实体名称及既有的跳转/资料窗口链接。
- 如果没有有效光标位置，实体仍可创建，但不插入 Markdown 链接。
- 保存带有关联对象的新实体后，关系记录立即写入项目；新实体及被关联实体各自的个人关系图同步刷新，无需重新分析。
- 如果用户没有选择关联对象，则允许创建独立实体，其个人关系图显示暂无关系，不根据“同一章节出现”自动编造人物关系。
- 现有“选中文字 → 关联已有实体/创建实体并关联”流程继续保留。
- 现有选中文字创建实体的流程也必须显示关联对象设置；不能再出现“文字已经链接、关系图却没有关系边”的不一致。
- AI 生成实体仍不可删除但可编辑；用户创建实体继续遵循项目既有的删除规则。

### F6 关系数据与关系图同步

- 模型分析、KP 在资料卡中创建、Markdown 编辑器创建以及既有关系编辑入口产生的关系，必须进入同一套规范化关系数据源。
- 新增关系后，关系两端实体的个人关系图立即出现对方和新关系，无需重新分析或刷新页面。
- 修改关系名称、方向、重要程度或端点后，受影响实体的个人关系图立即同步。
- 删除关系或删除允许删除的 KP 实体后，受影响关系图立即移除相应连线和无效节点，不保留悬空引用。
- 合并重复实体时，关系迁移到保留实体并按端点与语义去重。
- 重新分析可以替换模型生成的关系，但不得覆盖、删除或降级 KP 手动创建和编辑的关系。
- KP 编辑模型关系时保存为覆盖记录；KP 移除模型关系时保存为隐藏记录，重新分析后不得自动恢复。
- 人物被提升为核心人物或降为非核心人物后，核心人物关系图立即重新计算，无需调用模型。
- 核心人物关系图使用统一关系数据源中的“人物 ↔ 人物”关系；只要至少一端是核心人物，该关系及另一端人物就参与核心图展示。
- 核心人物与地点、线索、事件等非人物实体的关系只显示在个人关系图中，不进入核心人物关系图，避免图面过度拥挤。
- 关系同步属于本地数据派生，不因普通新增、编辑或删除操作调用模型 API。

### F7 核心人物卡编辑窗口拖动

- 从核心人物卡打开的编辑窗口支持通过窗口标题栏拖动。
- 拖动只改变编辑窗口在当前工作台中的位置，不改变人物卡在书页中的排版顺序。
- 输入框、下拉框、按钮、图片上传等交互区域不得触发拖动。
- 窗口不得被拖到视口之外；调整浏览器尺寸后仍保留可操作的标题栏和关闭入口。
- 拖动期间不丢失未保存的字段修改。

### F8 v1.0.0 发布收口

- 将项目对外版本标识统一更新为 `1.0.0`。
- 新增 v1.0.0 发布说明，概括 v0.9 基线和本规格新增能力。
- 不删除或重写现有项目数据；旧项目加载后使用新的目录和编辑会话逻辑。
- 完成 lint、build、test 和正式版端到端回归后，才可从候选版标记为正式 v1.0.0。

## 非功能需求

- N1：目录重建与标题编辑不得造成明显逐键卡顿；更新范围限制在当前编辑文档及目录模型。
- N2：编辑会话只在当前页面运行期间保存在内存中；刷新浏览器前仍需提示用户保存，避免误认为已经持久化。
- N3：拖动逻辑使用 Pointer Events，同时兼容鼠标和触控板。
- N4：键盘用户仍可操作编辑窗口中的全部字段和关闭按钮；拖动不是完成编辑的必要条件。
- N5：不得破坏 turn.js 单实例、双页显示、键盘翻页、目录跳转、实体预览或七阶段分析流程。

## 不做的事

- 不把 Markdown 内容改造成 PDF 或 Word 编辑器。
- 不新增 H7 或更深标题层级。
- 不新增组织实体模板。
- 不允许拖动核心人物卡改变书页排版或人物排序。
- 不在本版本中让所有实体编辑窗口都支持自由缩放。
- 不自动调用模型补写用户新建实体的内容。
- 不在核心人物关系图中展示地点、线索、事件等非人物节点。
- 不在跨页面导航时自动保存未完成草稿。
- 不改动分析协议、七阶段业务逻辑或 turn.js 的核心翻页实现。

## 验收标准

- AC1：在任一 Markdown 文档中依次新增 H1–H6，编辑器目录立即显示六级嵌套；保存后书页目录显示相同层级并可逐项跳转。
- AC2：创建两个同名子标题后，分别点击两个目录项，均跳到各自对应位置。
- AC3：无论第一幕内容是否被编辑或清空，目录始终显示一级“幕”，且所有幕均位于其下。
- AC4：修改最后一幕中的 H3 内容并保存，返回后直接显示包含该 H3 的书页，而不是第一页。
- AC5：在编辑器中产生未保存修改，进入“前期准备”再返回，仍处于原编辑模式，活动章节、目录状态、滚动位置和草稿均保持。
- AC6：点击取消后，本次草稿不写入项目，书页回到进入编辑器前的位置。
- AC7：未选择文字时点击“新建实体”，可以选择类型、输入名称、创建并打开可编辑资料窗口。
- AC8：在有效光标处创建实体并选择插入链接，Markdown 中出现实体名称链接，跳转和资料窗口行为正常。
- AC9：创建实体时关联一个已有角色并填写关系说明，保存后打开双方的个人关系图，均能看到对方和该关系；过程不发起模型请求。
- AC10：不选择关联对象时仍可创建实体，关系图保持空状态且不会自动生成推断关系。
- AC11：现有选中文字关联实体的流程仍可正常使用，若同时设置关联对象，文字链接和关系图同步更新。
- AC12：分别通过模型结果、资料卡和 Markdown 编辑器新增人物关系，双方个人关系图均立即出现该关系。
- AC13：编辑和删除一条关系后，双方个人关系图立即更新；删除实体后不出现悬空节点。
- AC14：重新分析人物关系后，模型关系按新结果更新，KP 手动关系仍完整保留。
- AC15：把一个非核心人物提升为核心人物后，与其相连的人物关系立即进入核心人物关系图；降级后立即退出。
- AC16：核心人物与人物的关系进入核心人物关系图；核心人物与地点、线索、事件的关系仅进入个人关系图。
- AC17：核心人物卡编辑窗口可从标题栏拖动；拖动输入框不会移动窗口，窗口无法完全移出视口，字段草稿保持。
- AC18：旧项目无需重新分析即可获得新的目录层级和编辑器行为。
- AC19：turn.js 翻页、双页显示、键盘翻页、七阶段分析、PDF/DOCX 原始资料和图片资料主流程回归通过。
- AC20：`npm run lint`、`npm run build`、`npm run test` 全部通过，并由独立验收 agent 输出无阻塞项的验收报告。
- AC21：“新增段落”按钮不再显示；撤销与恢复撤销按钮展示对应快捷键并能完成当前编辑会话内的操作。
- AC22：存在未保存草稿时返回项目首页或刷新页面会出现提示，取消离开后草稿仍在。
- AC23：KP 修改或隐藏模型关系后重新分析，KP 的覆盖或隐藏状态继续生效。

## 正式版判定

本规格实现完成后先作为 `v1.0.0-RC2` 验收。只有 AC1–AC23 全部通过，才更新正式发布状态并标记 `v1.0.0`。
