### B1 章节列表大面积重复（主要问题）

现象：

- 第 01–14 条全部显示 `从 9 至 9`。
- 第 15 条起又出现一遍 `02. 人物名录`、`03. 目击记录`……，序号看起来错乱。
- 列表总数 26 条，实际章节只有 14 个。

**根因 A：目录页被当作正文章节全文提取。**

- 该 PDF 无书签，`parsePdf` 的 `document.getOutline()` 返回空，章节完全依赖正文正则。
- `lib/parser.ts` 中 `headingPattern` 的最后一条分支 `[0-9]{1,2}[.、]\s*\S.{0,28}` 会命中目录页的每一行。
- 实测 **p9（标题「调查路线」，即目录页）命中 14 条**：`01. 档案检索` … `14. 城市公园`。
- 这些条目同在一页，`buildChapters` 算出 `endPage === startPage === 9`，所以整段显示 `从 9 至 9`。

**根因 B：`buildChapters` 只按 `(title, page)` 去重，不按标题去重。**

- 目录条目页码小排在前面，正文条目被挤到第 15 条之后。

**根因 C：目录标题与正文标题文字并不完全一致，不能只靠字符串去重。**

### B2 `printedPage` 全部被识别为 1

根因在 `detectPrintedPage`：

```14:24:lib/parser.ts
function detectPrintedPage(text: string): string | undefined {
  const lines = text
    .split("\n")
    .map(cleanLine)
    .filter(Boolean);
  const candidates = [lines[0], lines.at(-1)].filter(Boolean) as string[];
  const match = candidates
    .map((line) => line.match(/^-?\s*(\d{1,3})\s*-?$/))
    .find(Boolean);
  return match?.[1];
}
```

候选顺序是 `[首行, 末行]`，`.find(Boolean)` **优先取首行**。而本 PDF 每页顶部 y≈791 处有一个固定文本 `1`（页眉噪声），底部 y≈63 处才是真正的印刷页码。

实测：

| 页 | 顶部首行 | 底部末行 | 当前返回 | 期望 |
| --- | --- | --- | --- | --- |
| p2 | `1` (y791) | `2` (y63) | `1` | `2` |
| p9 | `1` (y791) | `9` (y63) | `1` | `9` |
| p63 | `1` (y791) | `63` (y63) | `1` | `63` |

影响：所有 `sources[].printedPage`、PDF 原文对照区的印刷页码全部错误。

### B3 双栏排版被逐行合并

现象：解析出的正文行把左右两栏拼接在一起。

实例（p2 第 2 行）：

```text
罗斯之猎犬发现了他， 追踪到了他所在的时 种改变脓液性质的药水， 使得它与人类的
```

根因：`parsePdf` 按 y 分行时容差为 ±2，左右栏处于同一 y 的文本被并入同一行。

```147:152:lib/parser.ts
    const rows: Array<{ y: number; items: typeof positioned }> = [];
    positioned.forEach((item) => {
      const row = rows.find((candidate) => Math.abs(candidate.y - item.y) <= 2);
      if (row) row.items.push(item);
      else rows.push({ y: item.y, items: [item] });
    });
```

影响：送往模型的正文语序错乱，检索片段质量与 `quote` 校验准确率下降。

### B4 模型连接失败（配置 + 网络，非代码缺陷）

1. **地址与模型不匹配**：截图中 `Base URL = https://api.openai.com/v1`，模型为 `deepseek-v4-flash`。
   `app/page.tsx` 在切换「接口协议」下拉时会无条件把 `baseUrl` 重置为该协议默认值，用户改完模型名后容易忘记改回地址：

```965:971:app/page.tsx

                  openai: "https://api.openai.com/v1",
                  anthropic: "https://api.anthropic.com/v1",
                  gemini: "https://generativelanguage.googleapis.com/v1beta",
                  ollama: "http://localhost:11434/api",
                } as const;
                onConfig({ ...config, protocol, baseUrl: defaults[protocol], capabilities: undefined });
```

2. **网络实测（当前机器）**：

   | 域名 | TCP 443 |
   | --- | --- |
   | `api.deepseek.com` | 通 |
   | `api.moonshot.cn` | 通 |
   | `api.openai.com` | **不通** |

   因此即使 Key 正确，请求打到 `api.openai.com` 也必然失败。这不是应用缺陷，需要在界面上给出明确指引。

3. **附带隐患**：`isDeepSeekEndpoint()` 仅按域名 `*.deepseek.com` 判断。使用第三方中转站时，`thinking: {type:"disabled"}` 与 `response_format: {type:"json_object"}` 不会下发，长文档会出现「只返回思考过程」或 JSON 解析失败。

## 二、修复要求

### F1 目录条目排除（必须）

- 新增目录条目判定：单页命中 **≥3 条** 标题，且其中存在 **3 个以上连续递增的编号**（例如 01…14）时，把这些编号行认定为目录条目；没有连续编号时，命中 **≥5 条** 则整组认定为目录条目。
- **只排除目录条目行，不整页跳过**：本 PDF 的目录排在第 9 页上半部分，下半部分紧接着第一章的正文标题 `01. 档案检索`。整页跳过会把正文标题一起丢掉，导致第一章凭空消失。
- **必须按行索引而不是行文本标记**：目录条目和正文标题的文字可能完全相同（第 9 页有两处 `01. 档案检索`），用文本作键会把正文标题一并排除。
- 「目录条目」的判据是**编号连续递增**：第 9 页的编号序列是 `1,2,…,14,1`，最长连续段为 `1…14`（目录），末尾孤立的 `1`（正文标题）自然被排除在外。
- 判定结果在「确认章节结构」界面提示「已排除第 N 页中的目录条目，该页的正文内容仍然保留」，导入与「重新读取 PDF 书签」的提示也会说明，不静默丢弃。
- 含目录条目的页号保存为 `Project.skippedTocPages`，随项目持久化。

### F2 章节去重与页范围补齐（必须）

- 章节按归一化标题去重：去除空白、统一全角/半角、统一间隔号 `·` 与中间点。
- 同名章节只保留**非 TOC 页**的那一条。
- **补齐首个标题之前的页范围**：第一个标题之前的内容（封面、故事背景、导入、展示材料等）不属于任何章节，而分析文本是按章节页范围收集的，不补齐就永远不会被送进分析。应在首个标题前插入一条覆盖 `1 … 首个标题页-1` 的章节，默认标题为「开篇」。
- 章节之间由 `endPage = 下一条 startPage - 1` 保证无缝衔接，不会出现中间空缺。
- 保留用户手动增删改章节的能力，`Chapter` 类型不变。

### F3 印刷页码（必须）

- `detectPrintedPage` 改为**优先取页面底部行**。
- 更稳妥：在整篇文档范围内统计首行与末行，排除「多数页面上固定出现的常量文本」（页眉噪声），再取剩余候选。
- 若首行与末行都不可用，返回 `undefined` 而不是错误值。

### F4 双栏拆行（建议，可独立提交）

- 通过检测「跨行重复出现的稳定空隙」定位分栏线：统计每行内相邻片段的**实际空隙**（前一片段右端到后一片段左端），找出在 **≥25% 的行**上重复出现、且落在页面 30%–70% 横向区间的那一条，即为分栏线。
- 拆栏后按阅读顺序输出：左栏整体在前，右栏整体在后。
- 不采用固定宽度比例阈值：实测本 PDF 栏间距只有 21pt，而栏内片段彼此重叠，任何「按宽度比例」的阈值都会失效；单栏文档的空隙位置分散，不会触发分栏。

### F5 模型连接引导（必须）

- 切换「接口协议」时不再无条件覆盖用户已填的 `baseUrl`；仅在用户未手动编辑过该字段时套用默认值。
- 地址与模型名明显不匹配时（例如 `baseUrl` 含 `api.openai.com` 而模型名以 `deepseek` 开头）在「测试连接」前给出前置提示。
- `isDeepSeekEndpoint` 放宽为按模型名或显式配置判断，不只认域名。
- 连接失败时展示服务端返回的原始错误信息，不要只显示「连接失败」。

### F6 中文序号标题与目录判定兜底

- `headingPattern` 增加 `一、二、三、` 形式的中文序号标题，此前只支持 `第X章 / 第X幕` 与阿拉伯数字 `1.`。
- 修正目录条目判定的兜底规则：原规则按「单页命中 ≥5 条标题」整组排除，在 Word 无目录（整篇压成一页）时会把正文标题全部误判成目录条目，导致章节退化成「全文」。改为只认**行号紧邻**的密集标题区，与目录条目「连续排列」的特征一致。
- 实测 `样本 C.docx` 由 1 个章节变为 13 个；其余三份样本文档章节数不变。

### 已知取舍

- 「开篇」是**首个标题之前无人认领内容的兜底名称**（本 PDF 为 1–8 页），标题是硬编码的通用词。它是为了保证这部分内容不被静默丢弃；需要更贴切的名字请在确认章节界面手动修改。
- 第 9 页同时含目录条目与第一章正文：目录条目被排除，该页剩余内容保留在 `01. 档案检索` 章节内。
- 分栏检测以「空隙在多数行重复出现」为依据，若某文档栏间距小于正文词距，仍会判为单栏，此时行为与修复前一致。
