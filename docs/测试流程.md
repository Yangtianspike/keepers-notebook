# 守秘人笔记本 · 测试流程与发布检查清单

## 一、命令

```powershell
npm run lint            # 代码规范检查
npm run test            # 构建 + 全部自动化测试（发布前必跑）
npm run test:coverage   # 额外输出覆盖率
```

`npm run test` 会先执行 `npm run build`，因此接口层测试跑的是**真实构建产物**（`dist/server/index.js`），而不是源码，可以捕获打包阶段的问题。

### 真实文档回归（本地手动运行）

```powershell
node scripts/verify-real-docs.mjs [模组目录]     # 默认扫描 桌面/跑团文件/模组
```

模组文件受版权保护、体积也大，不会进入仓库，因此这个脚本**不参与 `npm test`**。它会遍历目录下的所有 PDF 与 Word，输出每个文档的单位数、章节数、页覆盖情况与章节清单，并对「只识别出一个章节」和「存在无归属内容」给出警告。

变更解析逻辑（`lib/parser.ts`）后应当跑一次，确认真实文档没有回归。

## 二、自动化测试分层

| 层级 | 测试文件 | 覆盖内容 |
| --- | --- | --- |
| 解析层 | `parser-structure` · `docx-structure` · `parser-formats` | PDF 分栏还原、印刷页码、目录条目排除、章节构建、Word 目录分节、Markdown 分节 |
| 容错层 | `json-repair` · `quote-check` | 模型 JSON 修复、引用核对与未通过标记 |
| 数据层 | `entities` · `retrieval` · `storage-migration` | 实体卡构建与字段合并、文本分块、分词、BM25、旧存档迁移 |
| 模型层 | `model-adapter` · `provider-adapter` | 请求编排、三种确认模式、四种协议适配 |
| 接口层 | `api-model` | `/api/model` 参数校验、上游错误透传、网络异常、向量接口 |
| 渲染层 | `rendered-html` · `markdown` | 应用外壳渲染、Markdown 解析、URL 白名单 |
| 模板层 | `templates` · `coc-stat-extractor` | 章节模板生成、中文属性块提取 |

| `markdown.ts` | 75.75 % | 未覆盖的是 `editableHtmlToMarkdown`（需 DOM） |
| `storage.ts` | 44.04 % | 只覆盖了存档迁移，IndexedDB 读写需浏览器环境 |
| `app/` 组件 | 28.82 % | 仅验证应用外壳能渲染 |

两个读数字时要注意的地方：

1. **`all files` 整体约 34 %，分母包含 `dist/server/index.js`**（整个前端应用的打包产物）。它只在「渲染外壳」测试里执行过，必然拉低整体数字。判断质量应看分模块的行覆盖。
2. **行号存在小幅偏移**。`parser.ts` 报告 `559-564`（`parseScenarioFile`）未覆盖，但该函数已被测试覆盖，说明 Node 对 TypeScript 类型剥离文件的行号映射不完全精确。**应当关注「哪一大段连续区域未覆盖」（即某个函数从未被调用），而不是逐行精确比对。**

## 四、手工验收清单

自动化测试无法覆盖交互与浏览器存储，发布前按下面逐项手过一遍。

### A. 导入与章节结构

- [ ] 导入带文字层的 PDF：章节与页码正确，目录页被排除且界面有提示
- [ ] 导入无书签的 PDF：回退到正文标题识别，能给出合理章节
- [ ] 导入带目录的 Word：按目录分节，「开篇」覆盖目录与版权页
- [ ] 导入无目录的 Word：回退成单页「全文」，不报错
- [ ] 导入 Markdown：按 `#` 标题分节
- [ ] 导入不支持的格式（如 `.txt`）：给出明确错误提示
- [ ] 章节可以勾选 / 取消、标题与页码可以手动修改
- [ ] 「重新读取书签」在 PDF / Word / Markdown 上都可用

### B. 模型连接

- [ ] 正确填写 Base URL 与 API Key：测试连接成功
- [ ] 模型名与地址明显不匹配时出现黄色提示
- [ ] 网络不可达时错误信息包含**实际请求地址**，可据此排查
- [ ] 切换「接口协议」不会覆盖手填的第三方地址
- [ ] 勾选/取消「记住 API Key」行为符合预期

### C. 分析流程

- [ ] 七个阶段可以依次执行完成
- [ ] tier1 实时确认：模型提问时暂停，KP 裁决后继续
- [ ] tier2 / tier3 模式均能跑通
- [ ] 单个阶段重新分析不会清空其他阶段结果
- [ ] 分析日志记录了开始 / 暂停 / 完成 / 错误
- [ ] 来源引用可以跳回原文对应位置

### D. 阅读与编辑

- [ ] 书页翻页、排版、页码显示正常
- [ ] 人物卡与怪物卡正确渲染（不出现指令原文）
- [ ] 实体编辑后保存并立即生效
- [ ] KP 笔记可以新增、编辑、删除
- [ ] 图片资料包可以提取、拖入、移出

### E. 幕树

- [ ] 节点可以拖动，刷新后位置保持
- [ ] 「恢复默认布局」把两个模式一起重置
- [ ] 「只看主线 / 展开全部分支」切换后坐标不串位
- [ ] 边标签不被节点遮挡

### F. 数据持久化

- [ ] 刷新浏览器后项目、分析结果、KP 修改都还在
- [ ] 删除项目后不会重新出现
- [ ] 导入 60 页以上的 PDF 并完整跑完一轮分析

## 六、已知未覆盖区域

以下部分自动化测不到，改动它们时必须手工回归：

| 区域 | 原因 |
| --- | --- |
| IndexedDB 读写（`storage.ts` 大部分） | Node 测试环境没有 IndexedDB，只覆盖了纯函数迁移逻辑 |
| 各 React 组件（`app/components/*`） | 需要浏览器 DOM，仅通过构建产物验证外壳能渲染 |
| PDF 二进制解析（`parsePdf` 主体） | 需要真实 PDF 文件，测试只覆盖其纯函数部分（分栏、页码、目录、章节） |
| Word 二进制解析（`mammoth` 调用） | 同上，需要真实 `.docx` |
| 向量检索（`embedding.ts`） | 依赖外部嵌入服务，失败时会静默退化为关键词检索 |
| 模型真实输出质量 | 属于提示词效果，需要人工抽样评估 |
